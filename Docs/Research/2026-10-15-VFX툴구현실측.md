# VFXTool 1차 구현 실측 — 컴파일 · EditMode · U1 ~ U3 (2026-10-15)

**한 줄 요약** : 1차 구현(V1 ~ V12)을 시험 Unity 프로젝트에 붙여 돌렸다. 컴파일 오류 0, EditMode 47/47(최종), 템플릿 다섯은 두 번 돌려 프레임 해시가 같고 격자 비율이 모두 1.0 이다. 고리도 실물로 한 판(init → run → next → next → best) 돌았다.
머티리얼 이름표 셋 모두 스냅이 맞고, Lit 머티리얼은 2D 빛 색을 받는다. 잠금 · 타임아웃 · 인자 빠짐은 모두 종료 2 로 거절한다.
실측 중에 C# 버그 셋(그러데이션 fixed 키 뜻 · startFrame 단위 · 홀수 텍셀 스냅)과 Python 쪽 색 곱 함정 하나를 잡아 고쳤다.

앞 문서 : 설계 `../Design/2026-10-14-VFX툴설계.md`(9-2 시험 계획 U1 ~ U5) · 설계 전 실측 `2026-10-14-VFX툴실측.md`.
설계에서 바뀐 것은 설계 문서 13절에 모았다.

- warn 이 남은 까닭 : 다섯 모두 기본값 그대로 돌린 판이라 lopsided · first_empty 같은 모양 warn 이 남는다. 템플릿 값 손질은 U4(사람 눈) 뒤에 한다.

## 4. 미확인 넷 + 실측에서 잡은 버그

probe 진입점으로 Unity API 의 실제 뜻을 하나씩 쟀다.

| 항목 | 잰 것 | 결론 · 조치 |
| --- | --- | --- |
| step 곡선 | 키 [0:2, 0.4:1, 1:0.5] step → t 0 ~ 0.39 = 2, 0.4 ~ 0.99 = 1, 1 = 0.5 | 계단 맞음. 조치 없음 |
| **그러데이션 fixed 키 뜻** (버그 1) | Unity Fixed = 「t 에서, 시각 ≥ t 인 첫 키의 값」. 레시피 `[[0,1],[0.8,0]]` 이 0 넘자마자 알파 0 → 입자가 안 보임 | `VfxGradient.ToGradient` 가 fixed 키 시각을 다음 키 시각으로 민다 → 「t 부터 유지」 뜻이 됨. 고친 뒤 알파 1 이 0.8 까지 유지 |
| **textureSheet.startFrame 단위** (버그 2) | API 는 0 ~ 1 비율(2×2 시트 : 0.25 → 1번 칸 …, 1 넘으면 잘림). 레시피는 칸 번호 | `ApplyTextureSheet` 가 칸 수로 나눈다. 칸 = floor(값)이라 전 칸을 고르려면 `random [0, 칸 수]` |
| `Packages/…` 경로 풀이 | 현재 폴더가 프로젝트 폴더라 패키지 실제 자리로 풀림 | 조치 없음 |
| build `--save-root` | 프리팹 · 층별 `.mat` · 텍스처 · `<name>.recipe.json` 생김. GUID 참조 맞음. 텍스처 Point · mipmap 끔 · 압축 없음. 다시 build 하면 덮고 프리팹 해시 같음. 옆 파일 없는 폴더는 종료 2 · `../밖` 은 Python 이 종료 2 | 조치 없음 |
| Cone `[-90,0,0]` | 평균 속도 (0, 1, 0) — 위쪽. 회전 없으면 +Z(2D 에서 안 보임) | 설계 예시 `[0,0,90]` 을 고침 |
| Edge | 회전 없으면 X 축 가로선 · 속도 +Y. `[-90,0,0]` 이면 -Z | land_dust 는 회전 없이 씀 — 맞음 |
| Box | 속도 +Z (startSpeed 가 2D 에서 안 보임) | ambient_motes 는 velocityOverLifetime 로 움직여 괜찮음 |
| **홀수 텍셀 스냅** (버그 3) | 중심을 격자선에 맞추면 1 · 5 텍셀 입자 경계가 반 텍셀 어긋나 grid_ratio 0 | `VfxSnap.hlsl` 이 쿼드 한 변의 텍셀 수가 홀수면 중심을 텍셀 **한가운데**로 반올림. 고친 뒤 1 · 2 · 5 텍셀 모두 1.0 |
| 색 곱 (Python 쪽) | Unity 는 startColor × colorOverLifetime 색을 곱한다 | 내장 템플릿 그러데이션 색 키를 흰색으로, `recipe.color_multiply` warn 추가 |

## 10-15 밤 5판 — 무게중심 꼬리 문턱

**결론 : land_dust `symmetric_x` warn 의 원인은 렌더 쏠림이 아니라 표본 잡음이었다.** 한쪽에 입자가 2개뿐이라 생기는 잡음이, 입자가 ±15텍셀 바깥에 나간 꼬리 장(f9, 덮은 면적 1.5% 안팎)에서 커진다.
무게중심 규칙이 볼 장을 새로 정했다(`measure_rules.judged_frames`). 꼬리 장은 「최대 덮은 면적 장 **뒤**에 있고 면적이 `max(0.5%, 최대 × 0.25)` 미만인 장」이다.
`frame.lopsided` 의 평균과 문턱에도 같은 판정 장을 쓴다. 고친 뒤 land_dust 9시드 · hit_sparks 11시드 · 다른 셋에서 남은 warn 은 land_dust 시드 9 `centroid_rise_max` 8.2 > 8 하나였다. 옛 코드에서도 나던 진짜 상승이라, land_dust 문턱을 8 → 10 으로 올려 받았다(아래 「rise 문턱」). 이제 warn 은 없다.
