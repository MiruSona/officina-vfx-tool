# 도트 파티클 소재 조사 — 네모 하나 대신 어떤 그림을 조합하나 (2026-10-15)

## 0. 요약

- **답 : 맞다. 도트 이펙트는 작은 소재 그림 8~9종을 3~5층으로 겹쳐 만든다.** 세 갈래가 따로 조사해 같은 결론에 닿았다.
- 소재는 두 갈래다. **낱알**(1장 : 점 · 십자 · 4방 별 · 원 · 파편 · 늘인 줄)은 1~16px, **플립북**(여러 장 : 연기 · 불덩이 · 고리 · 별 반짝)은 8~32px · 5~13장이다.
- 색은 소재 하나에 1~4색. **흰색·회색 명도로 그려 두고 엔진에서 색을 입히는(틴트)** 팩이 여럿이다. 우리 색 곡선 방식과 그대로 맞는다.
- 층은 **번쩍(1~2장) → 코어 → 고리 · 파편 → 연기 · 잔여 점** 순서다. 사라질 때는 반투명이 아니라 **모양이 쪼개지며 픽셀이 줄어든다.**
- 우리 레시피는 이미 `texture`(시트 PNG) 와 `textureSheet`(tiles · fps) 칸이 있다. **`texture: "lib:<소재>"` 로 툴 안 소재 묶음을 가리키고, `textureSheet.row` 하나만 더하면** 된다 [추측].
- 첫 할 일 : 기하 소재 6종은 코드로 찍고, 연기 · 불덩이 플립북은 CC0 팩을 빌려 hit_sparks · land_dust 로 접촉판을 견준다.
- 그림 68장을 이번엔 **직접 열어 봤다.** 앞 조사(`2026-10-15-도트VFX레퍼런스조사.md`)의 「그림을 못 봤다」 한계를 메운다.

읽을 것 :

- **크기 사다리** : 낱알은 8px 안, 플립북은 8 · 12 · 16 · 20px 로 같은 소재를 크기별로 준다(Reactorcore 8→12→20→22→44) [실물]. 64텍셀이면 **16px 이 화면의 1/4** 이라 큰 소재는 코어 1~2개만 쓴다 [추측, C].
- **100px 칸 팩은 소재가 아니다.** CodeManu(100×100 · 41~121장 · 수백 색) · PVFX(96×96)는 「완성 이펙트」 플립북이다 [실물, 셋 다]. 모양 · 층 순서 참고용이다.
- **틴트용 1색 소재가 관례다.** DevWizard 는 「black and white assets are meant to be colored in your game engine」 이라고 적었다 [본문, B]. aj08coder · Aidan_Walker · Covalent 도 흰 1색 [실물, A · B].
- Kenney 512px 소재는 **검은 바탕 · 부드러운 그림**이다. 줄이면 흐린 반투명 픽셀이 생기므로 종류 지도로만 쓴다 [실물, 셋 다].

## 3. 조합(층) 관례

「근거」 열의 3D 분해글은 RealtimeVFX 의 폭발 분해(Atif, 2017-06-06, 18층 6묶음) 한 곳이다 :
https://realtimevfx.com/t/stylized-frag-launcher-explosion-overwatch-inspiration-breakdown-posted/1894?page=2
**셋 다 같은 글 하나를 인용했다** — 갈래 수가 셋이어도 출처는 하나다.

| 층 | 하는 일 | 소재 | 블렌드 | 수명 (12fps 장) | 근거 | 갈래 | 확신도 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 예고 | 터지기 직전 작게 | 작은 별 · 수축 고리 | additive | 1 | PVFX electric-impact · solar-shrapnel [실물] | 하나 (C) | 낮음 |
| 번쩍 | 맞은 순간 알림 | 원 · 4방 별, 흰색 | additive | 1~2 | 3D 분해글 「2~3프레임」 + Polar · BitingChaos 1장째 [실물] | **셋 다** | 높음 |
| 코어 | 가운데 덩어리 | 불덩이 · + 키움 플립북 | **갈림** (A · B add 또는 alpha, C alpha) | 4~7 | Polar burst 7장 · BitingChaos 5장 [실물] · 「빠른 속도 + 큰 감속」 [본문] | **셋 다** | 중간 |

층과 시간에 대한 공통 관찰 :

| 관찰 | 근거 | 갈래 |
| --- | --- | --- |
| 도트 이펙트 하나 = **3~5층**. 3D 의 18층은 과하다 | PVFX 실물 4~5층 [실물] · 나머지 [추측] | **셋 다** |
| 층 시작을 **2~3프레임씩 엇갈린다** | 3D 분해글 [본문] — 출처 하나 | **셋 다** |
| 작은 캔버스에선 층 여럿을 **한 플립북에 시간 순서로** 그린다(점 → + → 고리 → 점 4개) | Polar burst · BitingChaos [실물] | 둘 (A · C) |
| 사라질 때 **모양이 쪼개지며 픽셀 수가 줄어든다** (덩이 → 갈라짐 → 십자 점) | Knoble · Aidan_Walker · Reactorcore [실물] | 둘 (B · C) |
| 불 색은 **흰 → 노랑 → 주황 → 빨강(→ 보라 · 회색)** 으로 식는다 | Reactorcore · BitingChaos · CodeManu 6 [실물] | **셋 다** |
| 블렌드 관례 「빛 = additive, 연기 · 먼지 = alpha」 | 일반 상식 · Unity 셰이더 설명 [검색] — 원문 확인은 못 함 | **셋 다** |
| PVFX 시트는 반투명 없이 0/1 알파로 보인다 | 눈으로만 봄, 픽셀값은 안 셈 | 하나 (C) |

**블렌드가 갈린 까닭** : A 는 3D 관례를 따랐고, C 는 「도트에서 additive 겹침은 팔레트 밖 색(하양 날림)을 만든다」 며 번쩍만 additive 로 두자고 했다. B 도 같은 걱정을 적었다 [추측, B · C]. 우리 툴은 스냅 셰이더가 있어 결과가 어떨지 **아무도 실측 안 했다** → 7절 첫 실험에 넣는다.

## 4. Unity Shuriken 적용

셋이 같은 말을 한 것부터. 원문 : https://docs.unity3d.com/Manual/PartSysTexSheetAnimModule.html (A · C [본문], B [검색]).

| 할 일 | 설정 | 갈래 | 우리 설계와 견줌 |
| --- | --- | --- | --- |
| 시트를 고른 칸으로 자르기 | Mode **Grid**, Tiles X · Y 균등 | **셋 다** | 있음 (`textureSheet.tiles`) |
| 플립북을 우리 렌더와 1:1 로 | Time Mode **FPS 12** | **셋 다** | 있음 (FPS 고정) |
| 한 시트에 소재 여러 줄, 입자마다 줄 무작위 | Animation **Single Row** + Row Mode **Random** | **셋 다** | **없음 → `row` 칸이 필요** |
| 낱알 여러 변형 중 하나를 골라 고정 | Start Frame 무작위 + Frame over Time 상수 0 | 둘 (A · C) | 있음 (`startFrame: {"random": [0, n]}`) |
| 임포트 | Filter **Point** · Compression **None** · 밉맵 끔 | **셋 다** | 툴이 이미 맞춤 [추측 — 이번에 코드 안 봄] |
| 플립북 프레임 섞기 끔 | Frame Blending off | 하나 (B) | 있음 (끔 고정) |
| 수명 기준(Lifetime) 모드는 피함 | 수명이 다르면 장이 늘었다 줄었다 함 | 하나 (A) | FPS 고정이라 해당 없음 |

함정 (모두 **추측** — 실측 필요) :

- **팔레트 스냅 뒤 additive** : 겹친 자리가 팔레트 밖 색이 되거나 하양으로 날 수 있다. 스냅이 어디로 붙이는지 모른다 (B · C).
- **Size over Lifetime 깜박임** : 8px 소재를 크기 곡선으로 줄이면 Point 필터에서 픽셀이 빠졌다 붙었다 한다. 크기 대신 「큰 그림 → 작은 그림」 2~3장 플립북으로 작아지게 한다 (C, B 도 비슷한 말).
- **늘이기(Stretched Billboard)는 우리 설계에서 2차로 미뤘다**(설계 2-3절). 세 갈래가 다 「파편은 늘여 쓴다」 고 했지만 지금은 못 한다 → **1×4 · 1×6 줄을 그림으로 그려 둔** streak 소재로 대신한다 [추측, 합칠 때 찾음].
- 칸이 크고 그림이 작으면 텍스처 낭비 · 렌더 어긋남. CodeManu 칸 소수점 문제 보고가 있다 [검색, C] → 우리 소재는 칸을 그림 크기에 딱 맞춘다.

## 6. 우리 툴 적용 안 [추측 — 전부 제안]

### 6-1. 레시피 칸 : 새 칸 대신 있는 `texture` 를 넓힌다

세 갈래의 이름이 제각각이었다 — A `layers[].sprite` + `sprite_mode`, B `material{kind,size,frames,tint}`, C `material{kind,size,frames,variants}`.
그런데 **`material` 은 이미 `unlit`/`lit` 셰이더 갈래 칸이다**(설계 2-2절). 이름이 겹친다. 그리고 시트를 받는 `texture` · `textureSheet` 가 이미 있다.

```json
{ "name": "core", "blend": "alpha",
  "texture": "lib:burst16",
  "textureSheet": { "fps": 12, "row": "random" } }
```

- `texture: "lib:<소재>"` — 툴 안 기본 소재 묶음의 PNG 를 가리킨다. `px1` · `px2` · 파일 경로는 그대로 둔다.
- 소재 메타(칸 크기 · 장 수 · 줄 수)는 묶음 쪽 JSON 에 둔다. **`textureSheet.tiles` 를 안 적으면 메타에서 채운다** → 레시피가 짧아진다.
- 더할 칸은 **`textureSheet.row`** 하나 : 정수면 Single Row 그 줄, `"random"` 이면 Row Mode Random. 변형 소재(파편 3종 등)를 줄로 쌓아 둔다.
- 색은 지금처럼 `startColor` · `colorOverLifetime` 이 맡는다. 소재는 흰~회색 명도로만 그린다(A · B 관례).

### 6-2. 기본 소재 묶음 (9종)

| 이름 | 칸 크기 | 색 (명도 단) | 낱알/플립북 | 변형 · 장 | 갈래 | 본보기 |
| --- | --- | --- | --- | --- | --- | --- |
| `dot` | 3×3 | 1 | 낱알 | 1 · 2 · 3px 3변형(줄) | **셋 다** | Polar burst 끝 |

## 7. 다음 할 일 제안

### 7-1. 소재를 어떻게 만드나

| 방법 | 좋은 점 | 나쁜 점 | 맞는 소재 |
| --- | --- | --- | --- |
| **코드 생성** (Python 으로 픽셀 찍기) | 결정적 · 크기 변형이 공짜 · 저장소에 생성기만 두면 됨 | 연기 · 불처럼 손맛 있는 모양은 어렵다 | `dot` · `cross` · `disc` · `ring` · `shard` · `streak` (기하 6종) |
| **CC0 재사용** | 바로 쓸 수 있고 품질 검증됨 | 크기 · 칸이 우리와 다를 수 있음 · 출처 관리 | `puff8` · `puff16` · `burst16` (Reactorcore · BitingChaos · Polar) |
| **손그림** (Aseprite) | 가장 도트답다 | 사람 시간이 든다 | 나중에 CC0 를 갈아 끼울 때 |
| PixelLab 생성 | 이 세션에 `vfx_workbench` · `pixelart_workbench` 가 있다 | 유료 · 품질 안 시험함 | 시험해 볼 거리 |

**제안** : 기하 6종은 코드로 찍고(툴 안 생성기), 플립북 3종은 CC0 팩을 우리 칸 크기로 잘라 쓴다. 손그림은 그 다음.

### 7-2. 첫 실험 묶음

1. **hit_sparks 세 판 견줌** : (가) 지금 `px1` · (나) 기하 소재(`disc` + `ring` + `shard` + `streak`) · (다) (나) + `burst16` 플립북. 접촉판 셋을 나란히 본다.
2. **블렌드 실측** : 같은 (다) 판을 파편 · 고리 alpha / additive 로 두 번 → 스냅 뒤 색이 팔레트 밖으로 나가는지 measure 로 본다(3절 「갈림」 셋을 이걸로 정함).
3. **크기 곡선 깜박임** : `star4` 를 크기 곡선 판 vs 플립북 판으로 → 프레임별 픽셀 수가 튀는지 본다.
4. 위가 좋으면 land_dust 를 `puff16` + `shard` 로 바꾼다.
