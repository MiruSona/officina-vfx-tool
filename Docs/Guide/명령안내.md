# VFXTool 명령 안내 (2026-10-15 · 1차 구현 판, 3판 소재 묶음 · 7판 변형 묶음 반영)

명령 열세 개의 인자 · 종료 코드 · 보고 꼴과, 고리 한 바퀴를 손으로 도는 차례를 적는다.
**명령 · 옵션의 정본은 코드다.** 여기와 다르면 `vfxtool <명령> --help` 를 믿는다.
레시피 · 프로필 · 템플릿의 칸 뜻은 설계 `../Design/2026-10-14-VFX툴설계.md` 2 ~ 4절(바뀐 것은 13절)을, 소재 묶음(`lib:`)은 `../Design/2026-10-15-소재묶음설계.md`(바뀐 것은 끝 절)를, 변형 묶음(`variant`)은 `../Design/2026-10-15-변형묶음설계.md`(바뀐 것은 끝 「구현 뒤 정정」)를 본다.

아래 `vfxtool …` 은 `<VFXTool>\.venv\Scripts\python.exe -m vfxtool …` 로 친다. 처음이면 `setup.ps1` 을 한 번 돌린다.

## 0. 모든 명령에 같은 것

### 보고 꼴

stdout 에 JSON 한 덩어리를 쓴다. 사람이 읽을 글은 stderr 로 간다.

```json
{ "status": "ok|warn|fail|error",
  "issues": [{ "rule": "frame.palette", "layer": null, "frame": 3, "severity": "warn",
               "detail": "팔레트 밖 색 …", "hint": ["main.startColor", "colorOverLifetime"] }],
  "metrics": { … 명령마다 다름 … } }
```

| 칸 | 뜻 |
| --- | --- |
| `status` | issue 중 error 가 있으면 `fail`, warn 이 있으면 `warn`, 없으면 `ok`. 인자 · 파일 · 환경 문제면 `error` |
| `issues[].rule` | 규칙 이름. `recipe.*` · `template.*` · `patch.*`(레시피 단계) · `build.*` · `entry.*` · `render.*` · `unity.*`(Unity 단계) · `frame.*`(프레임 단계) · `loop.*` · `doctor.*` · `profile.*` · `variant.*`(13절) |
| `issues[].severity` | `error` · `warn` · `info` |
| `issues[].layer` · `frame` | 걸린 층 이름 · 프레임 번호(1부터). 프레임 규칙은 판 전체 그림으로 재므로 `layer` 가 `null` 인 일이 많다 |
| `issues[].hint` | 먼저 볼 레시피 칸. 증상표 `src/vfxtool/symptoms.json` 에서 온다 |

### 종료 코드

| 코드 | 뜻 |
| --- | --- |
| 0 | ok · warn |
| 1 | fail — error 규칙에 걸림(레시피 · 결과물 문제) |
| 2 | error — 인자 · 파일 · Unity 못 찾음 · 잠금 · 타임아웃 · 예외. **인자 오류도 같은 JSON 을 stdout 에 쓰고 2 로 끝난다** |

### 파일 자리

| 파일 | 자리 |
| --- | --- |
| 레시피 · 프로필 · 시트 PNG | 게임 쪽 아무 폴더. 레시피의 `profile` · `texture` 는 **레시피 폴더 기준 상대 경로** |
| 소재 묶음 | `src/vfxtool/lib/<이름>.png` + `<이름>.json`(메타) · 출처 `lib/sources.json`. 레시피는 `texture: "lib:<이름>"` 으로 부른다(11절) |
| 내장 템플릿 | `src/vfxtool/templates/<이름>.json` (다섯). 게임 쪽 템플릿은 `--templates <폴더>` 로 더한다(여러 번, 같은 이름이면 뒤 폴더가 이김) |
| 프리팹 | Unity 프로젝트 `Assets/Vfx/Generated/<name>/` (`--save-root` 로 바꿈, `Assets/` 안만. 조각 앞뒤 공백 · 끝 점(`bad ` · `bad.`) · 잘못된 파일 이름 글자(`a<b`)와 정션 · 심볼릭 링크 · 끊긴 링크가 낀 경로는 종료 2) |
| 작업 폴더 `--work` | job.json · result.json · unity.log · resolved.json 사본 · `frames/f###.png` · measure.json · sheet.png · preview.gif. **Unity 프로젝트 밖이어야 한다**(안이면 종료 2 — 안에 두면 PNG 마다 가져오기가 돈다) |

### `--input-root` 함정

레시피의 `profile` · `texture` 는 기본으로 **레시피 폴더 안**에 있어야 한다. `"profile": "../profile.json"` 처럼 위 폴더를 가리키면 `recipe.paths` error 로 막힌다.
그럴 때는 그 위 폴더를 `--input-root` 로 준다. 예 : 레시피가 `data/recipes/a.json`, 프로필이 `data/profile.json` 이면 `--input-root data`.
build · render 도 resolved 의 texture 를 한 번 더 본다(기본 resolved.json 폴더). 밖이면 Unity 를 안 띄우고 `recipe.paths` fail(1)로 끝난다.
`lib:` 소재는 예외다 — check 가 툴 안 lib 폴더의 절대 경로로 풀고, 그 폴더 PNG(메타 있는 것만)는 `--input-root` 밖이어도 통과한다. resolved.json 에 `lib:` 가 그대로 남았으면 `recipe.lib` error.
**시트 PNG 를 쓰는 레시피(sparkle 등)는 render 에도 check 때와 같은 `--input-root` 를 준다** — resolved.json 을 다른 폴더에 쓰면 시트가 그 폴더 밖이 된다(최종검증에서 밟음). `loop` 는 init 때 준 값을 바퀴마다 넘기므로 따로 줄 필요가 없다.

## 1. `profile` — VFX 프로필 만들기

```
vfxtool profile --from ref1.png [--from ref2.png …] [--style style.json] [--override hand.json] --out profile.json
```

- `--from` : 게임 스프라이트, **1:1 원본 크기**. 확대본이면 `profile.upscaled` info 가 붙는다(가장 짧은 같은 색 줄이 2 이상).
- `--style` : ArtTool 화풍 조각 JSON. 아는 키만 읽는다(대응표 `화풍조각대응표.md`). 모르는 키는 `profile.unknown_key` info.
- `--override` : 손 덮기. 가장 세다. 이기는 순서는 기본값 < PNG < 화풍 조각 < 손 덮기.
- metrics : `palette`(색 수) · `out`. 팔레트가 비면 종료 2.

## 2. `check` — 레시피 검사 · resolved.json

```
vfxtool check recipe.json [--profile profile.json] [--out resolved.json] [--input-root DIR] [--templates DIR …]
```

- 템플릿을 펼치고, `p<n>` 을 hex 로, 텍셀을 Unity 단위로, 도를 라디안(회전 칸)으로, from/to/ease 를 곡선으로 바꾼다.
- `--profile` 은 레시피 `profile` 칸 대신 쓴다. `--out` 은 error 가 없을 때만 쓴다.
- metrics : `layers`(펼친 뒤 층 수) · `out`.
- 규칙 표는 설계 8-1 + 13절. 자주 만나는 것 : `recipe.schema`(모르는 칸 — 가까운 이름 제안) · `recipe.pixel_size` · `recipe.color_multiply`(warn) · `recipe.paths` · `recipe.fixed`(템플릿 fixed 를 바꿈).
- 소재 · 시트 층 규칙(3판) :

| 규칙 | 등급 | 걸리는 때 |
| --- | --- | --- |
| `recipe.lib` | error | 없는 소재 이름 · `textureSheet.tiles` 가 메타와 다름 · `row` 가 소재 줄 수 밖 |
| `recipe.lib` | warn | 변형 여러 줄짜리 낱알 소재(`kind: grain`)에 `row` 를 안 적음 — 시트 전체가 넘어간다 |
| `recipe.lib_size` | **error** | lib · 파일 시트 층의 `sizeOverLifetime` 곡선 · `startSize` random · 곡선(끝점이 다름). 입자 크기가 소재 칸의 정수 배가 아님. 상수 배수는 된다 |
| `recipe.flipbook_life` | warn | 최대 수명 > 장 수 ÷ fps — 플립북이 처음부터 다시 돈다 |
| `recipe.flipbook` | error | 파일 시트의 `row` 가 줄 수 밖 (그밖 시트 규칙은 전과 같음) |

## 3. `patch` — 부분 덮기 뒤 check

```
vfxtool patch recipe.json patch.json --out new_recipe.json [--profile …] [--input-root DIR] [--templates DIR …]
```

- `recipe.json` 은 **템플릿 펼치기 전** 레시피다. 결과도 펼치기 전 꼴로 `--out` 에 쓰고, 바로 check 를 돈다.
- `--input-root` 기본은 `--out` 폴더다(상대 경로가 새 자리 기준으로 풀리므로).
- patch 를 거절하면(아래 규칙) `--out` 을 안 쓰고 종료 1. metrics : `out` · `layers` · `check`(check 의 status).
- patch 규칙은 5절.

## 4. `build` · `render` — Unity 배치

```
vfxtool build  resolved.json --project P [--save-root Assets/…] [--work DIR] [--input-root DIR] [--unity EXE] [--timeout 300]
vfxtool render resolved.json --project P --work DIR [--save-root …] [--input-root DIR] [--unity EXE] [--timeout 300]
                             [--fps N] [--backgrounds transparent|black,white]
```

- 입력은 **resolved.json**(check 결과)이다. 레시피를 바로 주지 않는다.
- `build` 는 프리팹만 만든다. `--work` 를 안 주면 resolved.json 폴더를 쓴다. 저장 폴더에 `<name>.recipe.json` 옆 파일이 없으면 사람이 만든 폴더로 보고 종료 2.
- `--save-root` 거절(종료 2) : 절대 경로 · `..` · `Assets/` 밖 · **조각 앞뒤 공백 · 끝 점**(Windows 가 몰래 벗겨 다른 폴더에 쓰므로 벗기지 않고 거절) · **잘못된 파일 이름 글자**(`Assets/a<b`). Unity 쪽은 모든 에셋 쓰기 경로가 한 길목(`VfxAssets.CheckedAssetPath`)을 지나며 **정션 · 심볼릭 링크 · 끊긴 링크**도 거절한다.
- `render` 는 프레임 PNG 만 뽑는다(프리팹 저장 안 함). `--work` 필수. 프레임은 `<work>/frames/f001.png …`, 상한 48장. 넘으면 `render.frames_capped` 와 metrics `truncated: true`.
- 프레임 시각(3판) : **`t = start + (i − 0.5)/fps`**, i 는 1부터. one-shot 은 start 0, loop 는 start = duration(한 바퀴 뒤). 장 k 가 플립북 k번 칸 가운데를 찍는다. 첫 장 0.0417초(fps 12). `i/fps` 는 칸 경계와 겹쳐 칸이 빠졌다.
- `--backgrounds black,white` 는 additive 디버그용 흑백 짝(`f###_k.png` · `f###_w.png`)을 더 뽑는다.
- Unity 찾기 : `--unity` > 환경 변수 `VFXTOOL_UNITY` > `ProjectSettings/ProjectVersion.txt` 의 Hub 기본 자리.
- 잠금 : 같은 프로젝트를 연 Unity 가 있거나 `Temp/UnityLockfile` 을 누가 쥐고 있으면 종료 2. 남은 잠금 파일만 있으면 `unity.stale_lock` info 로 진행한다.
- `--timeout` 을 넘으면 프로세스 나무째 끊고 종료 2. 기본 300초(첫 판은 컴파일로 1분 남짓).
- metrics : `mode` · `job` · `lock` · `exit_code` · `result` · `unity` · `prefab` · `frames` · `renderApi` · `graphicsDevice` · `seconds` · (render) `truncated` · `t0_skipped`.
- Unity 쪽 issue : `build.unknown_field` · `bad_value`(`textureSheet.row` 꼴 오류 포함) · `texture_sheet_row`(row 가 시트 줄 수 밖 — 시트 전체로 둠) · `mixed_modes` · `material` · `material_missing` · `texture_missing` · `texture_bad` · `entry.exception` · `entry.bug` · `unity.no_result`(result.json 이 안 생김). 실패하면 `unity.log` 의 `error CS` · `Exception` 줄을 issue 로 더 싣는다.

## 5. patch 꼴

```json
{ "layers": { "sparks": { "emission": { "bursts": [[0, 12]] }, "main": { "startSpeed": { "random": [30, 70] } } } },
  "duration": 0.45 }
```

| 규칙 | 뜻 |
| --- | --- |
| 합치기 | 객체는 겹쳐 합치고, 배열 · 값은 통째로 바꾸고, `null` 은 지운다(JSON Merge Patch) |
| `layers` 는 층 이름 열쇠 | `{층 이름: 덮을 값}`. 배열로 주면 `patch.layers_array` error |
| 못 바꾸는 칸 | `profile` · `name` · `version` → `patch.fixed_field` error |
| 없는 층 이름 | 새 층으로 덧붙이고 `patch.new_layer` warn. 이름에 점이 있거나 `main` 이 없으면 error(템플릿 층은 `main` 없어도 됨) |
| 템플릿 층 고치기 | 그 층의 `params` · `preset` · `override` 를 고친다. 펼친 이름(`hit.sparks`)으로는 못 고친다 |

## 6. `measure` · `sheet` · `gif` — 프레임 보기

```
vfxtool measure round_dir --profile profile.json [--recipe resolved.json] [--bw] [--out measure.json] [--source recipe.json] [--templates DIR …]
vfxtool sheet   round_dir [--measure measure.json] [--overlay] [--profile profile.json] [--out sheet.png]
vfxtool gif     round_dir [--scale 4] [--out preview.gif]
```

- `round_dir` 는 render 의 `--work` 폴더(result.json · `frames/` 가 있는 곳)다.
- `measure` : `--recipe` 기본은 그 폴더의 resolved.json(render 가 복사해 둠). 템플릿 프레임 규칙은 **펼치기 전 레시피**(`--source`, 기본 `<round_dir>/recipe.json`)에서 읽는다. `--bw` 는 흑백 짝으로 알파를 복원해 잰다.
- **함정** : 단독 `render` 판(고리 밖)에는 `<round_dir>/recipe.json` 이 없다. `--source` 를 안 주면 `template.*` 규칙이 조용히 안 돈다 — 펼치기 전 레시피를 꼭 `--source` 로 준다.
- textureSheet 층이 있는 판은 `frame.pixel_size` 를 info 로만 낸다(시트 칸 안 그림 모양이 입자 크기를 정하므로).
- `frame.bright` : 흰 번쩍이 **연속 3장 이상**이면 warn, 1 ~ 2장은 info(도트 관례).
- 무게중심 규칙(`template.symmetric_x` · `centroid_rise_max` · `centroid_rises` · `frame.lopsided`)은 같은 **판정 장**으로 잰다. 최대 덮은 면적 장까지는 덮은 면적 0.5% 미만만 빼고, 그 뒤 장은 `max(0.5%, 최대 × 0.25)` 미만(꼬리 장)을 뺀다. 다 빠지면 안 빈 장 모두로 잰다. 바깥으로 흩어진 끝 장은 입자 몇 개뿐이라 좌우 텍셀 수 차만으로 무게중심이 2 ~ 5 텍셀 튄다(10-15 land_dust 실측). 처음 뿜는 작은 장은 상승 · 치우침의 기준이라 안 뺀다. 뺀 장 수와 문턱이 detail 끝에 붙는다.
- measure metrics : `frames` · `colors` · `grid_ratio` · `coverage` · `centroid` · `max_luma` · `alpha_sum` · `semi_alpha` · `blobs`(덩어리 수) · `spread_x`(덩어리 무게중심 x 표준편차, 텍셀) · `width`(캔버스 폭, 텍셀) · `palette_out`(장마다 덮은 칸 중 허용 색 밖 비율, 0 ~ 1) · `symptoms`(자동 탐지 증상 낱말). 프레임마다 값 배열. 판 하나에 값 하나인 것 : `lopsided_limit` · `palette_out_mean`(안 빈 장 평균) · `flicker`(덮은 텍셀 수가 오르내림을 뒤집은 횟수, 보고만). 프로필 palette · fx_extra 가 비면 `palette_out` 은 None 이고 `measure.no_palette` info.
- `frame.lopsided` 는 무게중심 x 평균과 문턱을 모두 위 판정 장으로 낸다. 끝 장 0.1% 의 낱알 하나가 평균을 끌던 경계 warn(hit_sparks 시드 1234 · 9)을 막는다. 문턱 = `max(2, 2 × 평균(spread_x / √blobs))` 텍셀(판정 장 평균). 입자가 적고 넓게 흩어진 판은 무게중심이 우연으로 흔들리므로 그 폭의 2배까지 봐준다. 덩어리가 하나면 문턱 2 그대로. 상한은 캔버스 폭 1/4 — `min(문턱, max(2, width/4))`. 쓴 문턱이 `lopsided_limit` 에 실린다.
- **팔레트 여유 4.0** (7판) : `frame.palette` · `palette_out` · sheet `--overlay` 자홍 칸이 모두 `measure_metrics.PALETTE_TOLERANCE` 하나를 쓴다. 팔레트까지 RGB 거리 4.0 이하면 팔레트 안으로 본다(`palette_dist` 수치는 그대로 실림). Unity Linear 색 공간에서 입자 꼭짓점 색이 선형 8비트로 반올림돼 어두운 채널이 1 ~ 3 어긋나기 때문이다. 채널 값 18 아래처럼 아주 어두운 색은 그래도 warn 이 날 수 있다.
- `sheet` : 1줄 검정 배경 · 2줄 흰 배경, `--overlay` 면 3줄(팔레트 밖 자홍 · 격자 어긋남 노랑 · 무게중심 십자). AI 는 이걸 Read 로 본다.
- `gif` : 사람이 움직임을 보는 용도. 검정 배경 · nearest 확대 · 끝에 0.5초 멈춤.

## 7. `loop` — 고리

```
vfxtool loop init recipe.json --work DIR --project P [--profile …] [--templates DIR …] [--save-root …] [--input-root DIR] [--unity EXE] [--timeout 300] [--max 4]
vfxtool loop run  --work DIR
vfxtool loop next --work DIR [--critic critic.json] [--patch patch.json]
vfxtool loop best --work DIR
```

| 동작 | 하는 일 | Unity |
| --- | --- | --- |
| `init` | `<work>/<name>/` 에 장부 `loop.json` · `recipe.start.json` · `round_1/recipe.json`. 이미 있으면 종료 2 | × |
| `run` | 대기 바퀴 하나 : check → render → measure → sheet → gif 를 `round_N/` 에 | ○ |
| `next` | critic 을 마지막 판에 붙여 순위 · rollback · 멈춤을 판정. `--patch` 가 있고 안 멈췄으면 **최고점 판 레시피**에 대 다음 바퀴를 바로 돈다. `--patch` 없으면 판정만 | `--patch` 면 ○ |
| `best` | 최고점 판 폴더 · sheet · 점수 | × |

- `--work` 는 `loop.json` 폴더나 그 바로 위 폴더(아래에 고리가 하나뿐일 때)를 받는다.
- 순위 : ① error 수 적은 판 ② critic score 높은 판 ③ warn 수 적은 판, 같으면 나중 판. error · warn 은 **render · measure issue 만** 센다(check issue 는 보고에만).
- 실패 판(check fail · Unity error · 프레임 없음)은 바퀴를 안 쓴다. 같은 바퀴에 patch 를 다시 댄다. 두 번 연달아 실패하면 실패한 판 하나로 센다(순위 맨 뒤, 정체 셈에서 뺌).
- 멈춤 : `clean`(error 0 · warn 0 · score ≥ 0.9) · `max_rounds` · `stalled`(rollback 두 번 연속). critic 이 붙기 전 판은 rollback 판정을 미룬다.
- `run` · `next` 는 `loop.lock` 으로 한 판만 돈다. 다른 판이 돌고 있으면 `loop.locked` error. 판이 죽어 잠금이 남았으면 손으로 지운다.
- metrics : `loop` · `rounds_used` · `max_rounds` · `best{round, dir, sheet, errors, warns, score}` · `discarded_patches` · `stopped` · `stop_reason` (run 은 `round` · `measure` · `sheet` · `gif` · `note` 도).
- check 는 **원본 레시피 폴더 기준**으로 돈다. round 폴더로 옮긴 레시피의 상대 경로를 고치지 않아도 된다.

### critic.json (AI 가 씀)

```json
{ "score": 0.6, "symptoms": ["too_dense", "lingers"], "notes": "파편이 끝까지 남는다" }
```

`score` 는 0 ~ 1 숫자, `symptoms` 는 증상표 낱말(아래 9절)만.

## 8. 고리 손 흐름 한 번

```
1. vfxtool template show hit_sparks                     # 파라미터 · 프리셋 보기
2. (레시피 작성 — 템플릿 + params)
3. vfxtool check my_hit.json --input-root data            # Unity 전에 거른다. fail 이면 여기서 고침
4. vfxtool loop init my_hit.json --work D:\vfxwork --project <Unity 프로젝트> --input-root data
5. vfxtool loop run --work D:\vfxwork                     # round_1
6. round_1/sheet.png 를 Read · measure.json 의 issues · hint · symptoms 를 읽는다
7. critic.json · patch.json 을 쓴다
8. vfxtool loop next --work D:\vfxwork --critic critic.json --patch patch.json   # 판정 + round_2
9. 6 ~ 8 을 stopped 가 true 일 때까지
10. vfxtool loop best --work D:\vfxwork                   # 최고점 판 sheet 를 사람에게 보인다
```

마지막 판의 critic 만 붙이고 끝내려면 `loop next --critic critic.json`(patch 없이)을 한 번 더 친다.
프리팹이 필요하면 최고점 판의 `resolved.json` 으로 `build` 를 따로 친다(`loop best --build` 는 1차에 없다).

## 10. `template` · `doctor`

```
vfxtool template list [--templates DIR …]
vfxtool template show <이름> [--templates DIR …]
vfxtool doctor [--project P]
```

- `template list` metrics `templates[]` : `name` · `title` · `source`(어느 폴더) · `layers` · `presets`.
- `template show` metrics : `template`(JSON 전체) · `source` · `params[]`(이름 · type · default · min · max · desc · fallback). 모르는 이름이면 가까운 이름을 제안하고 종료 2.
- 색 파라미터의 `fallback` : 기본값이 팔레트에 없는 번호면(예 : 기본 `p1` 인데 팔레트가 한 색) 그 칸 대신 `fallback` 이 가리키는 파라미터 값을 쓴다. 레시피 · preset 이 직접 준 값은 안 바꾼다(틀리면 `recipe.palette` error). fallback 은 레시피 params 를 합친 뒤 적용하므로 **레시피가 고른 값을 따른다.** 템플릿 로드 때 검증한다(params 에 있는 color 파라미터 · 자기 자신 아님, 아니면 오류). 지금은 heal_rise `glow_color`(fallback `color`)만 있다.
- `doctor` : Python 패키지(없으면 `doctor.package` error) · `--project` 가 있으면 Unity.exe(`doctor.unity_exe`) · 잠금 · manifest 의 `com.officina.vfx` 줄(`doctor.manifest`) · Newtonsoft 줄(`doctor.newtonsoft`)을 본다. manifest 는 **보기만** 하고 고치지 않는다.

## 11. `lib` — 소재 묶음

```
vfxtool lib list
vfxtool lib show <이름>
vfxtool lib build [--only <이름>] [--out DIR]
vfxtool lib cut --source 원본.png --name <이름> [--tones 1|2] [--out DIR]
vfxtool lib cut --source 원본.png --name <이름> --ramp p0,p1,… --profile profile.json --out DIR
```

| 동작 | 하는 일 |
| --- | --- |
| `list` | metrics `lib[]` : `name` · `cell` · `tiles` · `kind` · `variants` · `made` · `license` |
| `show` | metrics `meta`(메타 JSON 전체) · `path`(PNG 자리) |
| `build` | 기하 7종(dot · cross · star4 · disc · ring · shard · streak)을 문자 그림 표(`lib_draw.py`)에서 다시 찍는다. `--out` 없으면 툴 안 lib 폴더를 덮는다 |
| `cut` | CC0 원본 띠를 `sources.json` 의 창으로 잘라 흰 실루엣 소재를 만든다. 원본 sha256 이 다르면 거절, 장당 잘림이 크면 `lib.clip` error. `--tones` 1 = 흰 1단, 2 = 흰 + 회색 50%(없으면 sources.json 의 `tones`, 그것도 없으면 1). 툴 안 lib 폴더에 쓴 판이면 쓴 tones 를 sources.json 에도 적는다 |
| `cut --ramp` | 팔레트 램프. 원본 명도를 `--ramp` 색(`p<n>` 쉼표, `--profile` 로 풂) 중 휘도가 가장 가까운 색으로 칠해 `<out>/<이름>_ramp.png` 한 장만 쓴다(메타 없음). 칸마다 가까운 휘도로 고르므로 **적는 순서는 상관없다** — 휘도가 같은 두 색만 앞에 적은 것이 이긴다. 팔레트 색이 알파 붙은 8자리면 거절. `--profile` · `--out` 필수, `--tones` 와 같이 못 씀, 툴 안 lib 폴더(와 그 아래)는 거절(종료 2). metrics `mapping`(원본 색 → 램프 색) · `recipe`(층에 붙일 조각) — 둘은 성공했을 때만 싣는다 |

- 플립북 3종 : `puff8`(Reactorcore SmokeThickPuff 8×8 · 9장) · `puff16`(Polar puff 16×16 · 10장) · `burst16`(BitingChaos 16×16 · 5장). 저장소 소재는 모두 흰 1단(`tones: 1`). 2단은 팔레트 밖 색이 나와 안 쓴다(실측). 원본 명도를 살리려면 `--ramp` 로 게임 팔레트 램프 PNG 를 만든다(아래).
- 레시피 꼴 :

```json
{ "texture": "lib:shard", "textureSheet": { "row": "random" } }
```

- check 가 `lib:` 를 **절대 PNG 경로 + tiles + fps**(안 적으면 프로필 fps)로 푼다. `tiles` 를 적었으면 메타와 같아야 한다.
- `textureSheet.row` : 정수면 그 줄만(Unity SingleRow · Custom), `"random"` 이면 입자마다 아무 줄(SingleRow · Random). 안 적으면 시트 전체(Grid · WholeSheet). row 를 고르면 장 수 = `tiles[0]`. 파일 시트에도 쓴다.
- 램프 PNG 를 쓰는 층(예 : hit_sparks core) — 레시피 폴더에 PNG 를 두고 override 한다. **startColor 는 `#FFFFFF`** 여야 텍스처 색이 그대로 나온다(Unity 는 텍스처 × startColor 를 곱한다) :

```json
{ "template": "hit_sparks", "params": { "core": true },
  "override": { "core": { "texture": "burst16_ramp.png", "main": { "startColor": "#FFFFFF" }, "textureSheet": { "tiles": [5, 1] } } } }
```

- 소재 · 시트 층의 크기는 **startSize 상수 하나**로 둔다. 크기를 바꾸려면 크기가 다른 소재 장을 플립북으로 넘긴다(`recipe.lib_size`).

## 12. 템플릿 계약 바뀜 (3판 · 4판 · 7판)

| 템플릿 | 바뀐 것 |
| --- | --- |
| land_dust | **`count` 뜻이 「한쪽 수」로 바뀜**(3판). 기본 2 · 범위 1 ~ 4(전 2 ~ 8), 프리셋 small 1 · big 3. **4판부터 층 6개가 모두 좌우 짝** — `puff_l` · `puff_r`(연기, `lib:puff16` 16px 10장 플립북 · 커졌다 흩어짐) · `small_l` · `small_r`(작은 점, `lib:dot`) · `chips_l` · `chips_r`(조각, `lib:shard`). 층마다 burst `$count` 라 `count` 는 여섯 층 모두 한쪽 수다. **override 층 이름 `puff` · `puff_small` · `chips` 는 없다** — 위 여섯 이름을 쓴다 |
| hit_sparks | 층 flash · ring · core · sparks · smoke. `core`(burst16 코어) 기본 false, `core_color` 기본 p1(fallback `color`) |
| 다섯 모두 | 소재(`lib:`)를 쓰는 여러 층. 블렌드는 템플릿 fixed — 번쩍 · 반짝 · 글로우 · 줄기 층(flash · twinkle · glint · glow · streak)만 additive, 파편 · 고리 · 연기 · 점은 alpha |
| 다섯 모두 (7판) | 시트 층의 `texture` · `main.startSize` 를 **`$<층>_tex` · `$<층>_size` 파라미터**로 뺐다(예 `sparks_tex` 기본 `lib:shard` · `sparks_size` 5). 좌우 짝 층은 한 쌍이 같이 쓴다(land_dust `puff_tex` · `puff_size`). 기본값이 옛 값과 같아 골든 resolved 는 바이트까지 그대로다. 레시피 override 로 `texture` 를 덮던 판도 그대로 이긴다 |
| file 파라미터 spec (7판) | 짝 키 셋 : `size`(짝 int 파라미터, 필수) · `tiles`(짝 tiles 파라미터, 있을 때만) · `color`(램프 때 `#FFFFFF` 로 바꿀 색 파라미터, 있을 때만). 짝이 없거나 꼴이 틀리면 템플릿 파일 오류(종료 2) |
| 템플릿 새 칸 `tiers` (7판) | 세기 표 `{이름: {mul: {파라미터: 배수}, scale: 정수}}`. 배수는 int · float 파라미터에만 · 0 < 배수 ≤ 100. **file 의 `size` 짝 파라미터(`*_size`)에는 배수를 못 건다** — 크기는 `scale` 몫이다. 다섯 템플릿 모두 weak · mid(빈 배수) · strong 을 갖는다. 13절 |

## 13. `variant` — 변형 묶음

같은 템플릿을 **속성 × 세기 × 시드**로 한 번에 펼쳐, Unity 한 번에 묶어 굽고 격자 접촉판 한 장으로 견준다. AI 는 짧은 묶음 JSON 하나만 쓴다.

```
vfxtool variant expand <묶음.json> --work DIR [--variants DIR …] [--templates DIR …] [--lib-src DIR] [--input-root DIR] [--force]
vfxtool variant run    --work <묶음 폴더> --project P [--only a,b …] [--unity EXE] [--timeout 초] [--save-root Assets/…] [--no-sheet] [--each]
vfxtool variant sheet  --work <묶음 폴더>
```

| 동작 | 하는 일 |
| --- | --- |
| `expand` | Unity 없이 `<work>/<묶음 name>/` 에 판 폴더 · `set.json`(장부)을 쓰고 판마다 check 를 돌린다. 판 상태는 `expanded` 또는 `failed` |
| `run` | `expanded` 판을 이름 순으로 render → measure → sheet · gif. **기본은 묶음** : 판마다 check · job.json → Unity 한 번(`jobs.json` 목록) → 판마다 measure · sheet · gif. `--each` 면 옛 동작(판마다 Unity 따로). 끝나면 `sheet` 를 부른다(`--no-sheet` 면 안 그리고 `next` = `variant sheet`). `done` 판은 건너뛰니 끊겨도 다시 부르면 이어 돈다. `--only` 는 여러 번 또는 쉼표, 모르는 이름은 종료 2, `expanded` 가 아닌 판은 info `variant.skipped` |
| `sheet` | `overview.png` · `strips_N.png` 를 다시 그린다 |

**묶음 돌리기 규칙**

- `--timeout` 기본은 없음(None) : `--each` 는 판 하나 300초, 묶음은 Unity 한 번에 60 + 20 × 판 수 초. 값을 주면 Unity 프로세스 하나의 상한이다.
- Unity 가 죽거나 시간을 넘기면 result.json 없는 판만 **한 번 더** 돌린다. 이때 첫 빈 판(Unity 를 죽였을 가능성이 큰 판)을 맨 뒤로 보낸다. 재시도 로그는 `unity_retry.log`.
- 재시도 전에 잠금을 다시 보고, 막히면 다시 안 띄운다. 첫 로그에 `error CS`(스크립트 컴파일 오류)가 있어도 다시 안 돌린다. 끝내 result.json 이 없는 판은 `variant.unity_lost`.
- `set.json` 최상위 `run` 칸 : `{mode, wall, unity_wall, retries, variants}`. `variants` 는 Unity 에 실제로 넘긴 판(준비에서 떨어진 판은 뺌). `--each` 면 `{mode: "each"}` 만.
- 묶음 12판 21초, 판마다(`--each`) 208초였다(실측 문서 「10-22 2차 A」).

### 묶음 JSON

```json
{ "version": 1, "name": "hit", "template": "hit_sparks",
  "profile": "../profile.json", "duration": 0.6, "seed": 1000,
  "params": { "ring": true }, "preset": null,
  "attrs": ["fire", "ice"], "tiers": ["weak", "mid", "strong"], "seeds": 2 }
```

- 판 수 = attrs × tiers × seeds, **상한 48판**(seeds 1 ~ 4). 판 이름 `<name>_<속성>_<세기>[_s<k>]`, 글자 `[a-z0-9_]`, 40자 넘는 판만 `variant.name` 실패 — 묶음 `name` 을 짧게 주면 풀린다.
- 판 k 의 시드 = `seed + k × 16`. 속성 · 세기가 달라도 같은 k 는 같은 시드라 줄끼리 「색만 다름」이 보인다.
- `attrs` 의 `"base"` 는 바탕 프로필 팔레트 그대로(예약어). `tiers` 에 즉석 객체 `{"name": "huge", "mul": {…}, "scale": 2}` 를 섞어도 된다.
- `duration` 기본은 템플릿 `max_duration`, 그 규칙이 없으면 1.0. 템플릿 check 에 `loop` 규칙이 있으면 그 값이 판 레시피 `loop` 칸에 들어간다.
- 묶음 `params` · `preset` 이 템플릿에 안 맞으면 판 하나가 아니라 묶음 오류(종료 2).

### 변형 사전 (속성)

툴 기본 `src/vfxtool/variants/{fire,ice,poison,lightning}.json` < `--variants <게임 폴더>`(여러 번, **같은 이름이면 파일 통째로** 뒤가 이김). 폴더 바로 아래 `*.json` 만, 파일 이름 = `name`, 64KB 상한, 심볼릭 링크 · junction 거절.

```json
{ "version": 1, "name": "fire", "title": "불",
  "palette": ["#FFF4A3", "#FFC23D", "#F2751A", "#C2321F", "#5E1914"],
  "max_colors": 8, "fx_extra": ["#FFFFFF"],
  "materials": { "lib:shard": "lib:dot" },
  "ramp": ["p0", "p1", "p2", "p3"],
  "params": { "color": "p2" } }
```

| 칸 | 뜻 |
| --- | --- |
| `palette` · `max_colors` · `fx_extra` | 바탕 프로필의 그 칸을 **통째로** 바꾼다. 판 폴더에 고친 `profile.json` 사본(바뀐 칸 `source` = `variant:<속성>`)을 써서 check · measure · sheet 가 그 팔레트로 판정한다. `max_colors` · `fx_extra` 는 선택 |
| `materials` | 소재 치환 `{바꿀: 새}`. `size` 짝이 있는 file 파라미터만 대상, `kind` · `tiles` 가 같아야 한다(아니면 `variant.material`). 짝 `size` = 새 소재 cell × 세기 `scale`. 템플릿이 안 쓰는 치환은 info `variant.unused_material` |
| `ramp` | 치환 오른쪽이 `ramp:<소재>` 일 때만 쓰는 램프 색 번호. 판 `tex/<소재>_ramp.png` 로 굽고 color 짝은 `#FFFFFF`. `--lib-src` 없음 · 원본 sha256 다름이면 그 판 `variant.ramp_source`. 기본 사전 넷에는 `ramp:` 치환이 없다 |
| `params` | 템플릿 파라미터 값. **겹침 : 묶음 `params` > 사전 `params` > 템플릿 기본.** 템플릿에 없는 이름은 info `variant.unused_param`, 꼴 · 범위가 틀리면 그 판 `variant.param` error. 기본 사전 넷은 `"color": "p2"` |

모르는 칸은 종료 2(오타를 바로 알린다). **속성 색이 안 갈리면 사전 `params` 로 색 파라미터를 중간 단(p1 · p2)으로 옮긴다** — 템플릿 `color` 기본 p0 은 사전의 가장 밝은 색이라 fire · ice 가 둘 다 흰빛이었다(7판 실측).

### 세기 (템플릿 `tiers`)

```json
"tiers": { "weak":   { "mul": { "count": 0.5, "speed": 0.7, "life": 0.8 } },
           "mid":    { "mul": {} },
           "strong": { "mul": { "count": 2, "speed": 1.3, "life": 1.2 }, "scale": 1 } }
```

- 바탕 값(템플릿 기본 < preset < 사전 params < 묶음 params)에 곱한다. int 는 반올림(0.5 올림), float 은 소수 자리 반올림. 0 < 배수 ≤ 100.
- `scale` 은 모든 `*_size` 짝 파라미터의 정수 배(기본 1). `*_size` 에 `mul` 을 걸면 템플릿 load · 즉석 세기 모두 거절.
- 곱한 값이 파라미터 min · max 밖이거나 inf · NaN 이면 **자르지 않고 그 판만** `variant.tier_range` 실패. 즉석 세기로 고친다.

### 산출물

```
<work>/<name>/
├─ set.json          ← 장부 : 묶음 원본(source) · 판 목록 · 판별 상태 · issues · 시간
├─ set.lock          ← run · expand --force 중에만
├─ overview.png      ← 줄 = 속성, 열 = 세기 × 시드. 칸은 덮은 면적이 가장 큰 장. FAIL 칸 자홍 X, 안 돈 칸 회색
├─ strips_N.png      ← 시간 띠. 판 12줄씩 한 장, 32장 넘는 판만 12장마다 줄 접기. 옛 strips 는 자동으로 지운다
└─ <판>/  recipe.json · profile.json · tex/ · (run 뒤) resolved.json · frames/ · result.json · measure.json · sheet.png · preview.gif
```

판 폴더는 고리 바퀴 폴더와 같은 꼴이라 `measure` · `sheet` · `gif` 를 그대로 쓴다. 고른 판은 그 `recipe.json` 을 게임 저장소로 가져가 `patch` · `loop` 로 다듬는다.

### 보고 · 종료 코드

| 코드 | 뜻 |
| --- | --- |
| 0 | 모든 판 expanded(expand) · done(run). warn · info 는 있어도 0 |
| 1 | 판 하나 이상 failed(펼치기 실패 · render · measure 실패 `variant.run`) |
| 2 | 묶음 · 사전 · 인자 오류 · 잠금(`variant.locked`) · Unity 못 찾음 · 에디터 열림 · `--work` 가 Unity 프로젝트 안 · `--force` 인데 묶음이 다름. 아무 판도 안 쓰거나 안 돌린다 |

metrics : `set`(set.json 자리) · `counts{total, expanded, failed, done}` · `variants[]`(name · attr · tier · seed · state · errors · warns · seconds · notes) · `timing{wall_total, unity_inside, unity_wall, per_variant_mean, mode, retries, measured, startup_ratio}`(done 이고 build · render 초가 있는 판만 셈, 없으면 null. 묶음은 `wall_total` = 묶음 한 번 벽시계, `unity_wall` = Unity 프로세스 시간. 판 `seconds.wall` 은 null) · `next` · run · sheet 는 `sheets[{path, size}]`.
묶음 `per_variant_mean` 은 묶음 벽시계 ÷ 잰 판 수라 실패 판에 든 시간도 들어 있다.
판 안의 check · render · measure issue 는 보고에 안 싣고 `set.json` 판 칸과 판 `measure.json` 에만 둔다. 보고에는 `variant.*` 한 줄씩만(`variant` 칸 = 판 이름).

| 규칙 | 언제 |
| --- | --- |
| `variant.name` · `palette_short` · `tier_range` · `material` · `param` | 펼칠 때 그 판만 failed. 이것들이 나면 check 는 안 돌린다(recipe.json 은 쓴다) |
| `variant.ramp_source` | `ramp:` 굽기 원본 문제 — 그 판 failed |
| `variant.check` | 판 check 에 error. 보고엔 규칙 이름 목록, 원본은 set.json |
| `variant.error` | 판 하나에서 뜻밖의 오류(오류 글 첫 줄). 그 판만 failed, set.json 은 끝까지 쓴다 |
| `variant.run` | render · measure 실패 → 판 failed |
| `variant.unity_lost` | error — 묶음에서 Unity 가 끝내 그 판 result.json 을 안 남김(죽음 · 시간 넘김). 그 판만 failed |
| `variant.log_span` | info — 묶음 로그에서 그 판 토막을 못 찾아 로그 줄을 안 붙임 |
| `variant.unused_material` · `unused_param` | info — 이 템플릿이 안 쓰는 치환 · 파라미터 |
| `variant.skipped` | info — `--only` 로 고른 판이 expanded 가 아님 |
| `variant.startup_heavy` | info — `--each` 에서만. `startup_ratio` > 0.5 면 Unity 기동이 대부분이라 묶어 굽기가 값어치 있다. 묶음에서는 안 낸다 |
| `variant.sheet` | warn — done 판 프레임을 못 읽어 접촉판 칸을 비움 |
| `variant.locked` | error(종료 2) — `set.lock` 이 있음 |

### `--force` 와 잠금

- 묶음 폴더가 이미 있으면 `expand` 는 거절한다. `--force` 면 판 폴더를 **지우지 않고** done 이 아닌 판만 다시 쓴다. run 의 failed 판을 다시 돌리는 길도 이것이다.
- `--force` 는 **같은 묶음으로만**. 옛 `set.json` `source` 와 `template` · `profile` · `duration` · `fixedTimeStep` · `seed` · `params` · `preset`, 같은 이름 세기의 몸이 같아야 한다. 다르면 종료 2 — 새 `name` 으로 펼친다. attrs · tiers · seeds 가 늘거나 순서만 바뀐 것은 된다. 장부에 없는 판 폴더가 있으면 거절.
- `run` 과 `expand --force` 는 같은 `set.lock` 을 쥔다. 막히면 `variant.locked` 종료 2. 앞 판이 죽어 잠금만 남았으면 hint 대로 `set.lock` 을 지운다(PID 확인은 아직 없다).
- `run` 은 돌릴 판이 있으면 맨 앞에서 Unity 찾기 · 에디터 열림을 한 번 본다 — 줄줄이 failed 가 되지 않게 종료 2 로 끝낸다.

### 함정

- **Git Bash 에서 `--unity` · `--project` 는 윈도 경로로** 준다(`cygpath -w`). `/c/…` 꼴이면 Unity 를 못 찾아 종료 2. PowerShell 이면 걱정 없다.
- `--each` 면 판 하나 약 17초 중 Unity 안 build + render 는 0.4초뿐이다(`startup_ratio` 0.977). 묶음이 기본인 까닭이다.
- 묶음 `profile` · 게임 텍스처가 묶음 폴더 밖이면 `--input-root` 를 준다. 게임 파일 텍스처는 판 `tex/<파라미터 이름>.png` 로 복사된다(PNG · 4MB 상한).
