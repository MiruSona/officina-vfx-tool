# VFXTool 게임 저장소에 붙이기 (사람 실측 U5 안내 · 2026-10-15)

게임 저장소의 Unity 프로젝트에 `com.officina.vfx` 를 붙이고, 이펙트 프리팹을 만들어 플레이 모드에서 눈으로 보는 차례다.
설계 9-2 의 **U5**(`../Design/2026-10-14-VFX툴설계.md`)가 이것이다. 아래를 위에서부터 따라 하면 된다.

> 이 문서는 실제로 게임 저장소에 붙여 보고 쓴 것이 아니다. 명령 꼴은 시험 Unity 프로젝트 실측(`../Research/2026-10-15-VFX툴구현실측.md` U1 ~ U3)과 코드에서 옮겼다.
> 글과 다르게 움직이면 `vfxtool <명령> --help` 와 `명령안내.md` 를 믿고, 다른 점을 `../Todo/` 에 적어 준다.

## 0. 먼저 알 것

| 말 | 뜻 |
| --- | --- |
| `<Officina>` | 스튜디오 저장소 폴더. VFXTool 은 지금 그 안의 `VFXTool/` 폴더다 |
| `<게임 저장소>` | Officina 형제 폴더인 게임 저장소. 툴은 `Tools/<툴>/` 서브모듈로 붙어 있다 |
| `<Unity 프로젝트>` | 게임 저장소 안의 Unity 프로젝트 폴더(`Assets/` · `Packages/` 가 있는 곳). 저장소 뿌리 바로 아래 한 단계 폴더다 |
| `<작업 폴더>` | 레시피 · 결과를 두는 폴더. **Unity 프로젝트 밖**이어야 한다(아래 예는 `C:\vfxwork`) |

**지금 VFXTool 은 아직 독립 저장소 · 서브모듈이 아니다.** 그래서 붙이는 길이 둘이다.

| | 분리 전 (지금) | 분리 뒤 |
| --- | --- | --- |
| 툴 자리 | `<Officina>\VFXTool` | `<게임 저장소>\Tools\VFXTool` (서브모듈) |
| manifest 줄 | Officina 를 가리키는 `file:` 경로 | `file:../../Tools/VFXTool/Unity/com.officina.vfx` |
| Python 설치 | `<Officina>\VFXTool\setup.ps1` | `<게임 저장소>\Tools\setup.ps1` (안에서 VFXTool `setup.ps1` 을 부른다) |
| 게임 저장소에 커밋 | **하지 않는다**(다른 기계엔 Officina 경로가 없다) | 서브모듈 · manifest · `packages-lock.json` 을 같이 커밋 |

**U5 는 분리 전 길로 해도 된다.** 보는 것(스냅 · 정렬 · 색)은 같다. 다 보고 나면 manifest 를 되돌린다(1-4).

## 1. 분리 전 — Officina 폴더를 그대로 가리키기

### 1-1. Python 설치 (한 번)

```powershell
powershell -NoProfile -File <Officina>\VFXTool\setup.ps1
```

끝에 `python -m vfxtool --help` 가 돌면 된다. 이 문서에서 `vfxtool …` 은 아래 꼴로 친다.

```powershell
$vfx = "<Officina>\VFXTool\.venv\Scripts\python.exe"
& $vfx -m vfxtool --help
```

### 1-2. manifest 에 두 줄 넣기 (사람이)

**툴은 남의 manifest 를 고치지 않는다.** `vfxtool doctor` 는 줄이 있나 보기만 한다. 사람이 넣는다.

`<Unity 프로젝트>\Packages\manifest.json` 의 `"dependencies": {` 안에 두 줄을 더한다.

```json
"com.officina.vfx": "file:C:/<Officina 자리>/VFXTool/Unity/com.officina.vfx",
"com.unity.nuget.newtonsoft-json": "3.2.2",
```

- `<Officina 자리>` 는 Officina 를 받은 절대 경로다. 경로는 **슬래시(`/`)** 로 쓴다.
- 상대 경로로 써도 된다. `file:` 상대 경로는 **`Packages` 폴더 기준**이다. 게임 저장소와 Officina 가 형제 폴더이고 Unity 프로젝트가 저장소 한 단계 아래면 `file:../../../<Officina 폴더 이름>/VFXTool/Unity/com.officina.vfx` 다(`..` 하나 = Unity 프로젝트, 둘 = 게임 저장소, 셋 = 그 위).
- Newtonsoft 줄이 이미 있으면 그 줄은 더하지 않는다. 판이 `3.2.2` 보다 낮으면 `3.2.2` 로 올린다.
- 마지막 줄 뒤 쉼표가 남지 않게 한다. JSON 이 깨지면 Unity 가 패키지를 하나도 못 읽는다.
- URP `com.unity.render-pipelines.universal` 은 `17.3.0` 이어야 한다(패키지가 그 판을 요구한다).

EditMode 시험까지 돌려 보려면 최상위(dependencies 밖)에 `"testables": ["com.officina.vfx"]` 도 넣는다. U5 에는 필요 없다.

### 1-3. 붙었나 보기

Unity 에디터를 한 번 열어 패키지를 받게 둔 뒤(Package Manager 에 **Officina VFX 0.1.0** 이 보이면 됨), **에디터를 닫고** 친다.

```powershell
& $vfx -m vfxtool doctor --project <Unity 프로젝트>
```

`status` 가 `ok` 면 된다. `doctor.manifest` · `doctor.newtonsoft` 가 뜨면 1-2 줄을, `doctor.unity_exe` 가 뜨면 Unity 찾기(6절)를 본다.

### 1-4. 다 보고 나서

manifest 두 줄을 지우고 `packages-lock.json` 을 되돌린다(`git checkout -- <Unity 프로젝트>/Packages`). 만든 프리팹 폴더(`Assets/Vfx/Generated/`)는 남길지 사람이 정한다.
**분리 전 manifest 는 게임 저장소에 커밋하지 않는다.**

## 2. 분리 뒤 — `Tools/VFXTool` 서브모듈로 붙이기

VFXTool 을 독립 저장소로 뗀 뒤의 길이다. 저장소 주소는 `https://github.com/MiruSona/officina-vfx-tool.git` 이다.

게임 저장소 뿌리에서 차례로 친다.

```powershell
git submodule add https://github.com/MiruSona/officina-vfx-tool.git Tools/VFXTool
git submodule update --init Tools/VFXTool
powershell -NoProfile -ExecutionPolicy Bypass -File Tools\setup.ps1
```

- `Tools\setup.ps1` 이 `Tools\VFXTool\setup.ps1` 을 불러 `.venv` 를 만든다. 서브모듈을 갱신한 뒤에도 다시 돌린다(`Tools\setup.ps1 -Check` 로 낡았나만 볼 수 있다).
- 이제 `$vfx = "Tools\VFXTool\.venv\Scripts\python.exe"` 다.

manifest 는 1-2 의 첫 줄을 이렇게 바꾼다(Newtonsoft 줄은 그대로).

```json
"com.officina.vfx": "file:../../Tools/VFXTool/Unity/com.officina.vfx",
```

`Packages` 에서 `..` 둘이면 게임 저장소 뿌리다. Unity 프로젝트가 저장소 뿌리에 바로 있으면 `file:../Tools/VFXTool/Unity/com.officina.vfx` 로 하나를 뺀다.

1-3 처럼 `doctor` 로 보고, `.gitmodules` · `Tools/VFXTool` · `manifest.json` · `packages-lock.json` 을 한 커밋으로 묶는다. 커밋 · 푸시는 게임 저장소 규칙대로 사용자 승인을 받는다.

## 3. 첫 이펙트 프리팹 만들기

U1 에서 실측한 템플릿 레시피 다섯을 그대로 쓴다. **build 는 Unity 를 배치 모드로 띄우므로, 게임 Unity 에디터를 닫고 친다.**

### 3-1. 레시피 · 프로필 옮기기

```powershell
New-Item -ItemType Directory -Force C:\vfxwork\out
Copy-Item <VFXTool>\Test\data\recipes C:\vfxwork\recipes -Recurse
Copy-Item <VFXTool>\Test\data\profile.json C:\vfxwork\profile.json
```

`<VFXTool>` 은 분리 전 `<Officina>\VFXTool`, 분리 뒤 `<게임 저장소>\Tools\VFXTool` 이다.
레시피는 `"profile": "../profile.json"` 으로 위 폴더를 가리키므로 `C:\vfxwork` 를 `--input-root` 로 준다(6절).

**`C:\vfxwork\profile.json` 을 열어 두 칸을 게임에 맞춘다.**

| 칸 | 넣을 값 | 안 맞추면 |
| --- | --- | --- |
| `ppu` | 게임 스프라이트의 Pixels Per Unit | 입자 한 칸이 게임 도트보다 크거나 작고, 격자가 스프라이트와 어긋난다 |
| `sorting_layer` | 이펙트를 그릴 Sorting Layer 이름(없으면 칸을 안 넣어 `Default`) | 없는 이름이면 `Default` 로 두고 `build.bad_value` warn |

팔레트도 게임 것으로 하려면 `vfxtool profile --from <게임 스프라이트.png> --out C:\vfxwork\profile.json` 으로 새로 만든 뒤 위 두 칸을 더한다(명령안내 1절). U5 첫 판은 시험 팔레트 그대로 둬도 된다.

### 3-2. check → build

맞음 파편(`tpl_hit_sparks`) 하나부터.

```powershell
& $vfx -m vfxtool check C:\vfxwork\recipes\tpl_hit_sparks.json --input-root C:\vfxwork --out C:\vfxwork\out\tpl_hit_sparks.resolved.json
& $vfx -m vfxtool build C:\vfxwork\out\tpl_hit_sparks.resolved.json --project <Unity 프로젝트> --save-root Assets/Vfx/Generated --input-root C:\vfxwork
```

- 둘 다 종료 0(`status` ok · warn)이면 된다. 첫 build 는 컴파일 때문에 1분 남짓, 그 뒤는 20초 안팎이다.
- `--save-root` 는 **`Assets/` 로 시작하는 프로젝트 상대 경로**만 받는다. 기본이 `Assets/Vfx/Generated` 라 빼도 같다. 게임이 다른 자리를 쓰면 이 값만 바꾼다.
- 산출물은 `<Unity 프로젝트>/Assets/Vfx/Generated/tpl_hit_sparks/` 에 생긴다.

| 파일 | 뜻 |
| --- | --- |
| `tpl_hit_sparks.prefab` | 이펙트 프리팹(이것을 씬에 놓는다) |
| 층별 `.mat` · 텍스처 | 프리팹이 쓰는 머티리얼 · 흰 점 텍스처(Point · mipmap 끔 · 압축 없음) |
| `tpl_hit_sparks.recipe.json` | 「툴이 만든 폴더」 표시. 이것이 없는 폴더는 툴이 덮지 않는다 |

나머지 넷도 같은 꼴로 만든다(이름만 바꾼다).

```powershell
foreach ($n in 'tpl_hit_sparks','tpl_land_dust','tpl_heal_rise','tpl_ambient_motes','tpl_sparkle') {
  & $vfx -m vfxtool check "C:\vfxwork\recipes\$n.json" --input-root C:\vfxwork --out "C:\vfxwork\out\$n.resolved.json"
  & $vfx -m vfxtool build "C:\vfxwork\out\$n.resolved.json" --project <Unity 프로젝트> --save-root Assets/Vfx/Generated --input-root C:\vfxwork
}
```

### 3-3. 씬에 놓기

1. Unity 에디터를 연다. 시험용 씬을 하나 만들거나 게임 씬을 연다(게임 씬이면 저장하지 않는다).
2. 카메라를 맞춘다 : **Orthographic · Size 10**. Game 뷰 해상도를 **1920×1080** 으로 고른다.
3. `Assets/Vfx/Generated/<이름>/<이름>.prefab` 다섯을 Hierarchy 로 끌어 놓는다. 캐릭터 · 바닥 스프라이트 옆에 두면 견주기 쉽다.
4. 플레이 모드에 들어간다. 한 번만 터지는 이펙트(맞음 파편 · 착지 먼지 · 회복)는 시작 때 한 번 돈다. 다시 보려면 그 오브젝트를 Hierarchy 에서 껐다 켠다.

Size 10 · 1080 줄이면 화면 세로가 20 유닛이다. PPU 32 면 640 텍셀이 1080 픽셀에 들어가 **텍셀 하나가 1.6875 픽셀** — 딱 나눠지지 않는 배율이다. U5 는 이 배율에서 도트가 버티는지 보는 판이다.

## 4. 플레이 모드에서 볼 것

한 줄씩 「통과 모양 / 실패 모양」이다. 실패면 어느 이펙트 · 어느 프레임쯤인지 적어 `../Todo/` 에 남긴다.

| 볼 것 | 통과 | 실패 |
| --- | --- | --- |
| **스냅 — 크기** | 입자 한 칸이 옆 스프라이트의 도트 한 칸과 같은 크기다. 비정수 배율이라 칸 폭이 1 픽셀 · 2 픽셀로 섞이는 것은 스프라이트도 같으니 통과다 | 입자 칸이 스프라이트 도트의 2배 · 반이다 → `ppu` 가 안 맞음 |
| **스냅 — 움직임** | 입자가 텍셀 단위로 「툭툭」 옮겨 간다. 가장자리가 늘 또렷하다 | 입자가 칸 사이를 미끄러지듯 부드럽게 움직이거나, 가장자리가 번지고 반투명 띠가 생긴다 |
| **스냅 — 격자 맞음** | 멈춘 프레임에서 입자 가장자리가 스프라이트 도트 경계와 같은 선에 있다 | 입자가 도트 경계와 반 칸씩 어긋나 있다(홀수 크기 입자에서 특히 본다) |
| **스냅 — 회전 · 크기 변화** | 돌거나 작아지는 중에도 칸 모양이 유지되고, 중간 한두 프레임이 깨져도 이어 보면 자연스럽다 | 도는 동안 계속 계단이 지글거리거나 칸 크기가 들쭉날쭉 튄다 |
| **정렬** | 의도한 앞뒤로 그려진다(예 : 맞음 파편이 캐릭터 앞, 바닥 먼지가 배경 앞) | 배경 뒤로 숨거나 UI 위를 덮는다 → `sorting_layer` · 층 `sortOrder` |
| **색 — unlit** | 프로필 팔레트 색 그대로 나온다(스포이트로 찍어 견준다) | 팔레트에 없는 색이 섞인다 · 하얗게 뜨거나 탁해진다 |
| **색 — lit** | 같은 자리의 스프라이트처럼 2D 빛 색을 받는다 | 빛을 줘도 색이 안 바뀌거나, 어두운 곳에서 혼자 빛난다 |
| **알파 · 테두리** | 입자 밖은 완전히 투명하다 | 입자 둘레에 검은 · 흰 네모가 보인다 · 분홍색으로 나온다 |
| **additive** | 겹치는 곳이 더 밝아진다(원래 그런 블렌드다) | 어두운 배경에서도 안 보인다 · 밝은 배경에서 통째로 하얗게 탄다 |

## 6. 자주 막히는 자리

| 증상 | 까닭 · 할 일 |
| --- | --- |
| build 가 종료 2 · 「잠금」 | 같은 프로젝트를 연 Unity 에디터가 있다. 에디터를 닫고 다시 친다. 남은 `Temp/UnityLockfile` 만 있으면 `unity.stale_lock` info 로 그냥 진행한다 |
| build · render 가 종료 2 · 작업 폴더 거절 | `--work`(안 주면 resolved.json 폴더)가 Unity 프로젝트 안이다. 작업 폴더를 프로젝트 밖으로 옮긴다 |
| sparkle 만 `recipe.paths` 로 종료 1 | 시트 PNG 가 resolved.json 폴더 밖이다. **build · render 에도 check 때와 같은 `--input-root`** 를 준다 |
| check 가 `recipe.paths` error | 레시피의 `profile` · `texture` 가 레시피 폴더 위를 가리킨다. 그 위 폴더를 `--input-root` 로 준다 |
| build 가 종료 2 · 저장 폴더 거절 | `--save-root` 가 `Assets/` 로 시작하지 않거나 `..` · 절대 경로다. 또는 같은 이름 폴더가 이미 있는데 `<이름>.recipe.json` 이 없다(사람이 만든 폴더라 안 덮는다) — 이름을 바꾸거나 폴더를 비운다 |
| Unity 를 못 찾음(`doctor.unity_exe`) | `ProjectSettings/ProjectVersion.txt` 판의 Hub 기본 자리에서 찾는다. 다른 자리면 `--unity <Unity.exe>` 를 주거나 환경 변수 `VFXTOOL_UNITY` 를 둔다 |
| 게임 화면 색이 판정 PNG 와 다르다 | 툴은 **후처리를 끄고** 렌더한다(켜면 배경 알파가 죽는다). 게임 카메라의 Bloom · Tonemapping · Color Adjustments 가 켜져 있으면 색이 달라지는 게 맞다. 툴 탓인지 보려면 카메라 Post Processing 을 잠깐 끄고 견준다 |
| lit 이 빛을 안 받는다 | 실측은 **URP 17.3 2D 렌더러**(Renderer2D)에서만 했다. 게임이 다른 렌더러면 Light2D 가 안 닿는다 — 확인 못 한 자리라 Todo 에 적는다 |
| 분홍색 입자 | 셰이더를 못 읽었다. URP 판(17.3.0) · 패키지가 Package Manager 에 있나 · Console 의 셰이더 오류를 본다 |
| 색이 팔레트 밖으로 곱해진다(레시피를 고쳤을 때) | Shuriken 은 `startColor` × `colorOverLifetime` 을 곱한다. 색은 startColor 에만 두고 그러데이션 색 키는 `#FFFFFF` · 알파만 쓴다(`recipe.color_multiply` warn) |
| render 가 프레임을 못 뽑는다 | GPU 가 있는 기계에서 `-batchmode` 로만 돈다. 원격 · 헤드리스 기계, `-nographics` 로는 안 된다 |
