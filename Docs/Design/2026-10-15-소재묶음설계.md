# VFXTool 3판 — 소재 이미지 묶음(lib) 설계

> 2026-10-15 · 근거 : `Docs/Research/2026-10-15-도트파티클소재조사.md` 6 · 7절 (사용자 「결정은 권장대로」)
> 앞 설계 : `Docs/Design/2026-10-14-VFX툴설계.md` · 구현 실측 : `Docs/Research/2026-10-15-VFX툴구현실측.md`

## 0. 결론 먼저

- 입자 그림을 **1×1 네모(`px1`)에서 툴 안 소재 10장 묶음**으로 바꾼다. 레시피는 `texture: "lib:<소재>"` 한 줄로 고른다.
- **Python 이 `lib:` 를 다 풀어 절대 경로 · 칸 수를 resolved.json 에 넣는다. C# 은 lib 를 모른다.** C# 이 새로 할 일은 `textureSheet.row` 하나다.
- 소재는 **흰색 1단 실루엣(알파 0/1)** 으로만 만든다. 조사 안의 「회색 2~3단」은 버렸다 — Unity 가 텍스처 × startColor 를 곱해서 회색 단이 곧 팔레트 밖 색이 된다(앞 설계 2-5 · 13절 함정).
- 기하 7종(dot · cross · star4 · disc · ring · shard · streak)은 **생성기**로 찍고, 플립북 3종(puff8 · puff16 · burst16)은 **CC0 원본을 잘라** 넣는다. 둘 다 결과 PNG 를 저장소에 넣는다.
- 기하 소재 칸은 **홀수 크기**(3 · 5 · 7 · 15)로 바꿨다. 가운데 픽셀이 있어야 + · 원이 대칭이고, 스냅 셰이더의 홀수 규칙(구현실측 4절)과도 맞는다.

## 1. 목표와 범위

지금은 모든 입자가 한 텍셀 네모라 「점이 흩어진다」 이상의 모양이 안 나온다. 3판은 **모양을 가진 작은 그림 10장**을 툴에 넣고, 템플릿 다섯을 이 그림을 쓰는 여러 층으로 다시 짠다.

| 하는 것 | 안 하는 것 (다음 판) |
| --- | --- |
| 소재 10장 · 메타 · 생성기 · 자르기 명령 | Stretched Billboard (속도 방향 줄) — `streak` 은 세로 · 대각 줄을 그림으로 대신 |
| 레시피 `lib:` · `textureSheet.row` | 손그림(Aseprite) 소재 · PixelLab 생성 |
| C# Single Row · Row Mode | 회색 여러 단 소재 (팔레트 램프 — 7절 위험 R1) |
| 템플릿 다섯 다층화 · 실험 세 판 | U5(게임 저장소에 붙이기) |

## 2. 소재 묶음 구조

### 2-1. 자리

```
VFXTool/src/vfxtool/
├─ lib/                    ← 데이터만 (py 없음)
│  ├─ dot.png · dot.json   ← 소재마다 시트 PNG + 메타 JSON
│  ├─ ...
│  └─ sources.json         ← CC0 원본 출처 · 자르기 창 (2-4)
├─ material_lib.py         ← 메타 읽기 · 이름 → 경로 풀기 · 검사
├─ lib_draw.py             ← 기하 7종 생성기 (문자 그림 → PNG)
├─ lib_cut.py              ← CC0 원본 자르기 · 흰 실루엣 바꾸기
└─ commands/lib.py         ← `vfxtool lib list | build | cut | show`
```

- `pyproject.toml` 의 `package-data` 는 지금 `**/*.json` 뿐이라 PNG 가 빠진다. `"lib/*.png"` 를 더한다.
- `lib/` 는 패키지가 아니라 데이터 폴더다. `vfxtool.lib` 이름을 import 와 겹치지 않게 py 를 두지 않는다.

### 2-2. 메타 JSON 꼴

```json
{ "name": "ring", "cell": 15, "tiles": [4, 1], "frames": 4, "rows": 1,
  "kind": "flipbook", "variants": [], "blend": "alpha",
  "made": "draw", "source": null, "license": "MIT (VFXTool 생성)" }
```

| 칸 | 뜻 |
| --- | --- |
| `cell` | 한 칸 한 변 텍셀 수. **늘 정사각** (빌보드 쿼드가 정사각이라서) |
| `tiles` | `[가로 칸 수, 세로 칸 수]` = `[frames, rows]` |
| `kind` | `grain`(낱알, 1장) · `flipbook`(여러 장을 수명 동안 넘김) |
| `variants` | 줄마다 이름. 줄이 변형일 때만 (예: shard `["l2", "l3", "blob4"]`) |
| `blend` | 권장 블렌드. 검사는 안 한다(참고용) |
| `made` · `source` · `license` | `draw` / `cut` · `sources.json` 열쇠 · 라이선스 |

### 2-3. 열 장 표

조사 6-2 는 「9종」이라 했지만 puff8 · puff16 을 한 종으로 센 것이다. 파일은 10장이다.

| 이름 | 칸 | tiles | 꼴 | 만듦 | 조사안과 다른 점 |
| --- | --- | --- | --- | --- | --- |
| `dot` | 3 | [1, 3] | 낱알 3변형(줄) | draw | — |
| `cross` | 5 | [1, 3] | 낱알 3변형(줄) | draw | 변형 하나 더(빈 십자) |
| `star4` | 7 | [4, 1] | 플립북 4장 | draw | 8 → **7** |
| `disc` | 7 | [1, 1] | 낱알 1장 | draw | 8 → **7**, 2~3단 → **1단** |
| `ring` | 15 | [4, 1] | 플립북 4장 | draw | 16 → **15** |
| `shard` | 5 | [1, 3] | 낱알 3변형(줄) | draw | 4 → **5** |
| `streak` | 7 | [1, 3] | 낱알 3변형(줄) | draw | 1×6 → **7×7 칸 안 줄** (쿼드가 정사각) |
| `puff8` | 8 | [9, 1] | 플립북 9장 | cut | — |
| `puff16` | 16 | [10, 1] | 플립북 10장 | cut | — |
| `burst16` | 16 | [5, 1] | 플립북 5장 | cut | 3~4단 → 1단 |

### 2-4. 공통 픽셀 규칙

- 칠한 칸 = `(255, 255, 255, 255)`, 빈 칸 = `(0, 0, 0, 0)`. **반투명 0개.**
- 빈 칸 RGB 를 0 으로 두는 까닭 : additive(One One)는 알파를 안 곱해서, 빈 칸에 색이 남으면 네모가 비친다.
- 색은 레시피 `startColor` · `colorOverLifetime` 이 맡는다(지금과 같음).

## 3. 만드는 방법 둘

### 3-1. (가) 생성기 — 기하 7종

`vfxtool lib build [--only <이름>] [--out <폴더>]` 가 `lib_draw.py` 의 **문자 그림 표**를 PNG 로 찍는다. 같은 입력이면 늘 같은 픽셀이다(난수 없음). `#` = 칠함, `.` = 빈 칸.
`--out` 을 안 주면 `src/vfxtool/lib/` 를 덮는다. 시험은 임시 폴더에 찍어 저장소 PNG 와 **픽셀 배열**로 견준다(PNG 바이트는 Pillow 판마다 다를 수 있어 안 본다).

```

.#.   .##   ###
...   .##   .#.
```

```
.###.   #####   #.#.#
..#..   ..#..   .....
.....   ..#..   ..#..
```

```
...#...   ..###..   #######   ...#...

.......   .......   ...#...   .......
.......   .......   ...#...   .......

```

```
.#####.

.#####.
```

### 3-2. (나) 자르기 — 플립북 3종

원본 PNG 는 **저장소에 안 넣는다**(사용자 결정). 사람이 URL 에서 받아 `vfxtool lib cut --src <원본.png> --name puff16` 으로 자른다. 결과 PNG 만 저장소에 들어간다.
자르기 창과 출처는 `lib/sources.json` 에 적어 둔다. 원본 sha256 도 적어서, 다른 파일을 주면 거절한다.

이번 세션 스크래치패드의 실물을 열어 칸 크기 · 장 수 · 잘림을 쟀다.

| 이름 | 원본 (CC0) | 원본 칸 · 장 | 우리 칸 | 창 (x, y) | 잘려 나가는 픽셀 |
| --- | --- | --- | --- | --- | --- |
| `puff8` | Reactorcore Fire Smoke Animations — `SmokeThickPuff.png` (72×8) | 8 · 9장 | 8 | (0, 0) | 0 |
| `puff16` | Polar_34 Particles Pack 2 — puff strip (320×32) | 32 · 10장 | 16 | (8, 7) | 장별 2·1·0·0·4·0·0·0·0·2 (합 9) |
| `burst16` | BitingChaos 16x16 Explosion — `explosion_sheet.png` (80×16) | 16 · 5장 | 16 | (0, 0) | 0 |

자르는 규칙 :

1. **크기를 바꾸지 않는다.** 축소(최근접 포함)는 금지 — 픽셀이 빠지거나 두 배가 돼 도트가 깨진다. 칸이 크면 **고정 창으로 잘라내고**, 작으면 가운데에 빈 칸을 덧댄다.
2. 창은 모든 장에 **같은 자리**다. 장마다 옮기면 플립북 중심이 흔들린다.
3. 잘려 나가는 불투명 픽셀이 **장당 5개를 넘으면 실패**(종료 1). puff16 은 최대 4개라 통과.
4. 흰 실루엣 바꾸기 : 알파 > 0 이면 흰색 · 알파 255, 아니면 (0,0,0,0). 원본 명도는 버린다.

고른 까닭 : puff8 은 원본이 이미 8칸이라 손댈 게 없다. puff16 은 Reactorcore SmokePoff(20칸)가 창 16에서 장당 최대 12픽셀이 잘려 Polar puff 를 골랐다. burst16 은 원본이 16칸 그대로다. Polar burst(7장, 잘림 0)는 모양이 `star4` · `ring` 과 겹쳐 뺐다.

`THIRD-PARTY.md` 에 「그림 소재」 표를 새로 만들어 세 줄(이름 · 저자 · URL · CC0 · 우리가 바꾼 것 = 자르기 · 흰 실루엣)을 적는다. CC0 는 표기 의무가 없지만 출처 관리용이다. **CC-BY · CC-BY-SA 소재는 넣지 않는다.**

## 4. 레시피 칸과 풀이

### 4-1. 레시피 꼴

```json
{ "name": "shards", "texture": "lib:shard",
  "textureSheet": { "row": "random" } }
```

- `texture` : `px1` · `px2` · 파일 경로 그대로 + **`lib:<이름>`**.
- `textureSheet.row` (새 칸) : 정수 `0 ≤ row < rows` 면 그 줄만(Single Row · Custom), `"random"` 이면 입자마다 줄을 고름(Row Mode Random). 안 적으면 지금처럼 시트 전체(Grid · WholeSheet).
- `textureSheet.tiles` 를 안 적으면 메타에서 채운다. 적었는데 메타와 다르면 error.
- **낱알 소재(frames = 1, rows = 1, 예: disc)는 `textureSheet` 를 안 적어도 된다.** 변형 줄이 있는 낱알(dot · cross · shard · streak)은 `row` 를 적어야 한 칸만 보인다 — 안 적으면 `recipe.lib` warn(시트 전체가 넘어감).

### 4-2. 어디서 풀리나 — Python 이 다 푼다

`resolve_layer` 가 `lib:ring` → `<패키지>/vfxtool/lib/ring.png` 절대 경로로 바꾸고, `textureSheet.tiles` 를 메타로 채운다. resolved.json 의 `texture` 는 지금 파일 텍스처와 똑같은 절대 경로다.
C# 은 지금처럼 「절대 경로 파일이면 읽는다」(`ResolveTextureFile`)만 한다.

이렇게 정한 까닭 :

- 앞 설계 1-2 「C# 은 단위 · 팔레트를 모른다」와 같은 원칙이다. 메타가 한 곳(Python)에만 있다.
- UPM 패키지에 PNG 를 복사해 둘 필요가 없다. 소재를 고쳐도 Unity 쪽은 그대로다.
- 골든 시험이 Python 안에서 끝난다. 경로는 `<LIB>` 로 바꿔 견준다(지금 `<DATA>` 와 같은 수법).

| `recipe/fields.py` `field_problems` | `row` 꼴 검사 더함 (`tiles` 갈래 옆) |

## 5. C# 바뀌는 곳

| 자리 | 바뀌는 것 |
| --- | --- |
| `Runtime/VfxTextureSheetModule.cs` | `[JsonProperty("row")] public VfxRow Row;` — 정수 또는 `"random"`. 작은 `JsonConverter` 로 가른다(`VfxValueConverter` 와 같은 수법) |
| `Editor/VfxLifetimeModules.cs` `ApplyTextureSheet` | `Row == null` → 지금 그대로(Grid · WholeSheet). 있으면 `animation = SingleRow` · 정수면 `rowMode = Custom` · `rowIndex = n` · random 이면 `rowMode = Random` |
| 같은 함수 `ToNormalizedFrame` | SingleRow 면 칸 수 = `numTilesX`(한 줄 길이)로 나눈다. **Unity 가 그렇게 셈하는지 실측 필요** (EditMode 시험 E3) |
| (고칠 것 없음) | 모르는 모듈 칸은 `VfxFields.Extra` → `build.unknown_field` 로 알린다. `Row` 칸을 선언하면 끝이라 따로 키 목록은 없다 |

임포트 설정은 **이미 있다**. 메모리 텍스처는 `LoadImage` 뒤 `filterMode = Point` · `Clamp` · mipmap 없이 만들고(`VfxMaterialFactory.LoadTexture`), 저장할 때는 `VfxAssets.SaveTexture` 가 Point · 압축 없음 · mipmap 끔 · sRGB · alphaIsTransparency · NPOT 그대로를 건다. 고칠 것 없다.

## 6. 템플릿 다섯 바꾸기

### 6-1. 공통

- 기본 블렌드는 alpha, additive 는 **번쩍 · 반짝 · 글로우 · 상승 줄기**만. 조사 6-3 의 「갈림」 셋(파편 · 고리 · 상승 입자)은 **우선 alpha** 로 두고 실험 2 로 정한다.
- 수명은 「장」을 fps 12 로 바꾼 초다(1장 = 0.083초). 플립북 층 수명 = 장 수 ÷ 12 로 맞춰 다시 돌지 않게 한다.
- 시트 층의 `startSize` = 소재 `cell`. 크기 곡선은 플립북 층에 안 건다(깜박임, 실험 3).
- 기존 파라미터 이름(count · palette · color · sheet · tiles 등)은 **그대로 둔다.** 기본값 · 범위만 바뀐다. 선택 층은 bool 파라미터 + `when` 으로 켠다.

### 6-2. 층 표

| 템플릿 | 층 | 소재 · row | 블렌드 | 수명 | 개수 | 켬 |
| --- | --- | --- | --- | --- | --- | --- |
| hit_sparks | flash | `disc` | additive | 0.083~0.166 (1~2장) | 1 | 늘 |
| | core | `burst16` 플립북 | alpha | 0.416 (5장) | 1 | 늘 |
| | ring | `ring` 플립북 | alpha | 0.333 (4장) | 1 | `ring` (기본 true) |

### 6-3. 템플릿 하나하나 주의

- **hit_sparks** : `sparks.blend` 는 `fixed` 에 그대로, 새 층 셋도 `fixed` 에 블렌드를 넣는다(사람이 override 로 additive 를 섞지 못하게 — 실험 2 결과가 나오면 푼다). `last_frame_empty` 가 있으니 모든 층 수명 ≤ duration.
- **sparkle** : `start_frame_random` 규칙을 **뺀다.** 지금 시트는 아무 장부터 시작해도 됐지만 star4 는 「점 → 별 → 점」 한 번이 한 생이라 0 장부터 돌아야 한다. 어긋남은 방출 시각이 흩어져서 생긴다. `tiles` 기본 [4, 1] 은 star4 와 같아 그대로. `size` 기본 5 → **7**. `twinkle.blend` fixed 는 alpha → **additive**. `sheet` 는 이제 필수가 아니다.
- **land_dust** : `symmetric_x 2텍셀` 규칙이 있다. puff 는 좌우 둘씩 짝으로 쏜다(버스트 2개 · `shape` Edge 양끝) — 짝이 안 맞으면 무게중심이 쏠린다.
- **ambient_motes** : `coverage_max 5%` 규칙. glint 는 1~2 개라 넉넉하다.
- **heal_rise** : 지금 층 이름 `dots` · `glow` 를 그대로 둔다(기존 레시피 override 가 안 깨지게).

## 7. 실험 설계 (조사 7-2)

모두 OfficinaTest 에서 `vfxtool loop` 없이 `check → render → measure → sheet` 한 번씩. seed 고정 · 64×64 · scale 4.

**실험 1 — hit_sparks 세 판**

| 판 | 내용 |
| --- | --- |
| 가 | 지금 판(`px1` 파편 하나 층) — 2판 결과를 그대로 다시 씀 |
| 나 | flash `disc` + ring + sparks `shard` (burst16 없음) |
| 다 | 나 + core `burst16` |

견줄 것 : 접촉판 셋 나란히 · GIF · measure 의 `frame.*` issue 수 · `palette_out` · `grid_ratio` · coverage 최대.
통과(나 · 다) : `frame.palette` · `frame.grid` warn 0 · `palette_out` = 0 (alpha 층만인 장) · 마지막 장 비었음 · coverage 최대 ≤ 30%(64캔버스에서 너무 크지 않게). 어느 판을 기본으로 할지는 **사람이 접촉판을 보고** 정한다 — 숫자로는 「모양이 낫다」를 못 잰다.

**실험 2 — 블렌드**

다 판을 `sparks` · `ring` 각각 alpha / additive 로 4판. 판정 : additive 판의 `palette_out`(비지 않은 장 평균)이 **≤ 0.02** 이고 `frame.colors` warn 이 없으면 additive 를 허용, 아니면 alpha 로 굳힌다. 겹친 additive 칸은 fx_extra 흰색으로 포화되지 않는 한 팔레트 밖이 된다 — 이 비율을 보는 실험이다.

**실험 3 — 크기 곡선 깜박임**

입자 1개 · 퍼짐 0 · 0.333초. (ㄱ) `cross` row 0 + `sizeOverLifetime` 1 → 1.4 → 1, (ㄴ) `star4` 플립북. 프레임별 덮은 텍셀 수를 본다.
통과 : `flicker` ≤ 1(산 하나), `grid_ratio` 1.0 모든 장. 예상은 ㄴ 통과 · ㄱ 실패(5 × 1.4 = 7 이 아닌 사이 값에서 모양이 깨짐). ㄱ 이 실패하면 「시트 층에 크기 곡선 금지」를 `recipe.lib_size` warn → error 로 올린다.

**실험 4** — 위가 통과하면 land_dust 새 판(`puff16` + `shard`)을 같은 관문으로 본다. `symmetric_x` · `centroid_rise_max` 통과가 추가 관문.
