## 2. 소재 `bolt32` 규칙

### 2-1. 꼴

| 칸 | 값 | 까닭 |
| --- | --- | --- |
| cell · tiles | 32 · `[8,1]`(frames 8 · rows 1) | 사각형 칸이라 `meta_problem` · `recipe.lib_size`(32 의 정수 배) 그대로 통과. Unity `tiles` 는 아무 [x,y] 나 받는다(`VfxLifetimeModules.cs`) |
| 그리는 자리 | x 8~23 · y 0~31 (16×32). 나머지 열은 빔 | 조사 7절 (가) |
| kind · blend · made | flipbook · alpha · draw · source null · `MIT (VFXTool 생성)` | `lib_draw.meta()` 그대로. tones 칸은 안 붙인다(cut 전용) |
| 픽셀 | 글자 → 회색 불투명 : `#` 255 · `1` 191 · `2` 127 · `3` 63, 빈 칸 (0,0,0,0) | 단 번호 0~3 = 램프 번호 p0~p3 (3절) |
| 장 수 · 시간 | 8장 × 83ms = 0.666초 | 조사 「전체 5~8장」 · 12fps 고정 |
| 위 · 아래 | 칸 y0 = 줄기 꼭대기, y31 = 바닥 | 템플릿이 입자를 y +15 에 놓아 칸 바닥이 원점에 닿는다(4절) |

### 2-2. 그림 규칙 (좌표 x 오른쪽 · y 아래, 칸 안 0~31)

| 이름 | 정의 |
| --- | --- |
| 줄기 꼭짓점 | A(15,0) → B(12,8) → C(19,13) → D(13,21) → E(15,28). **큰 꺾임 3번**(B · C · D). B→C 가 가로로 크게 꺾는 「ϟ」 마디 |
| 중심선 | 마디마다 Bresenham 1px(8방향) |
| 심(2px) | 중심선 + 이웃 한 칸. 세로가 긴 마디(\|dy\| ≥ \|dx\|)는 (x+1, y), 가로가 긴 마디는 (x, y+1) |
| 테(1px) | 심의 8-이웃 팽창 − 심, 칸 밖은 버림 |
| 갈래 2 | L : B(12,8)→(9,12)→(8,15) · R : C(19,13)→(22,16)→(23,19). 1px |
| 바닥 원 8×3 | y29 x13~18 · y30 x12~19 · y31 x13~18 (조사 7×3 을 짝수 가운데 15.5 에 맞춰 8) |
| 바닥 원 10×4 | y28 x12~19 · y29~30 x11~20 · y31 x12~19 |
| 고리 | 원의 바깥 둘레(원 − 4-이웃 안쪽) |

### 2-3. 장별 표

| 장 | 뜻 | 그림 (글자 = 단) |
| --- | --- | --- |
| 0 | 예고 | `1` : 바닥 점 (14,31) · (17,31) + 꼭대기 중심선 A→(14,3) 1px |
| 1 | **피크** | 심 `#` + 테 `2` + 갈래 L · R `2` + 바닥 원 8×3 `#` |
| 2 | **피크 유지(지직)** | C → (20,13), D → (12,21) 로 1px 옮긴 줄기 : 심 `#` + 테 `2` · 갈래 `3` · 바닥 원 10×4 `1` 에 가운데 y29~30 x14~17 `#` · 짧은 가시 `2` (11,26) (11,27) (20,26) (20,27) |
| 3 | 심이 빔 | 장 1 줄기의 테 자리만 `1`, 심 자리는 빔 · 바닥 10×4 고리 `2` |
| 4 | 토막 | 중심선 1px `2` 중 y 0~6 · 11~17 · 22~27 세 토막 · 바닥 12×4(x10~21, y28~31) 고리 `3`, (x+y) 짝수 칸만 |
| 5 | 바닥 갈래 기어감 | `3` : (13,29)→(9,31) · (18,29)→(22,31) |
| 6 | 불씨 6 | `3` : (11,24) (20,22) (13,18) (18,27) (9,29) (22,29) |
| 7 | 불씨 3 | `3` : (12,21) (19,24) (15,27) |

- 효과의 마지막 장(장 9, t 0.708)은 입자 수명 0.666 이 끝나 빈다 → `frame.last_not_empty` 를 피한다.
- 장마다 색 수 ≤ 4(장 2 가 4) → `max_colors` 4 안.
- **무게중심 규칙** : 칠한 장마다 무게중심 x 가 15.5 ± 1.5 안에 있어야 한다(시험으로 묶음). 벗어나면 꼭짓점 x 를 1px 씩 옮겨 맞춘다. symmetric_x 를 빼는 대신 이것으로 대칭을 지킨다.

### 2-4. 코드 자리 (`lib_draw.py`)

| 고칠 것 | 내용 |
| --- | --- |
| `TONES = {"#": 255, "1": 191, "2": 127, "3": 63}` | `render` 의 `if char == "#"` 를 `if char in TONES` → (v,v,v,255) 로. 기존 ART 는 `#` 만 써서 기존 PNG 바이트가 그대로다(시험이 본다) |
| `_line(p, q)` | Bresenham 점 집합. `midpoint_circle` 옆 |
| `_bolt_frames()` | 장마다 [(글자, 점 집합), …]. 뒤에 칠한 것이 앞을 덮는다(테 → 심 차례) |
| `_tone_art(layers, cell)` | `_points_to_art` 의 글자 판. ring 은 그대로 `_points_to_art` |
| `spec("bolt32")` · `names()` | ring 가지 옆에 한 가지 · 목록에 `"bolt32"` |
| `paint_tones(rgba, ramp)` | 알파 > 0 칸 → `ramp[clip(rint((255 − R) / 64), 0, len−1)]`, 나머지 (0,0,0,0). 흰 1단 소재는 모두 p0 이 된다 |
| docstring | 「기하 소재 7종 · 흰 1단」 → 「8종 · bolt32 만 밝기 4단(램프 굽기용)」 |

**규칙 그리기 vs 문자 그림 표** : 표로 넣으면 32줄 × 8장 = 256줄이다. 규칙으로 그리면 꼭짓점 상수에 약 40줄이고 「지직」(꼭짓점 1px 옮김)도 한 줄이다 → **규칙 그리기**.

굽기 : `python -m vfxtool lib build --only bolt32` → `lib/bolt32.png`(256×32) · `bolt32.json`. sources.json 은 안 건드린다.

### 3-1. 세 길 비교

| 기준 | (ㄱ) 소재에 노랑을 칠함 + color 흰 | **(ㄴ) 밝기 단 소재 + `ramp:` 넓히기** | (ㄷ) 밝기 단 + Unity 색 띠 |
| --- | --- | --- | --- |
| 코드 양 | lib_draw 글자 → hex 표 ≈ 5줄 | lib_draw ≈ 5줄 + `paint_tones` ≈ 8줄 + `variant_ramp` 가지 ≈ 12줄 | 그라디언트 맵 셰이더 · 머티리얼 팩토리 · resolved 칸 · 스키마 · 시험. 수백 줄 |
| 팔레트 검사 | 칠한 hex 가 판 팔레트 ∪ fx_extra 에 있을 때만 warn 0 → **lightning 사전 하나에서만** 통과. 게임 바탕 팔레트로는 warn | 판 팔레트로 칠하니 늘 palette_dist 0(10-15 D 판 실측 0.0 과 같은 길) | Linear 변환 · 보간 섞임 위험. 측정 안 해 봄 |
| 다른 속성에 재활용 | 불가. 노랑이 박혀 fire · ice 마다 소재 사본이 든다 | 사전에 치환 한 줄이면 그 팔레트 번개 | 가능 |
| 원칙 | **어긴다** — 「lib 는 모든 게임이 같이 쓰는 흰 소재, 팔레트는 게임마다」(`lib_cut` docstring · `cut_ramp` 가 lib/ 쓰기 거절) | 지킨다 | 지킨다 |
| 약점 | — | 사전 없이 쓰면 회색 × 색 → frame.palette warn (10절 R3) | 가장 큼 |

### 3-2. 선택 : (ㄴ)

| 고칠 자리 | 내용 |
| --- | --- |
| `variant_ramp.ramp_params` | `material in sources` 면 지금 그대로. 아니면 `material_lib.load(material)` 의 `made == "draw"` 일 때 tiles · cell 을 메타에서 가져온다. 둘 다 아니면 `variant.ramp_source` 「sources.json 에도 만든 소재에도 없다」 |
| `variant_ramp._bake` | 램프 번호 → hex 풀기를 맨 앞으로 옮긴다. 만든 소재면 `--lib-src` 없이 `material_lib.path` 의 PNG 를 읽어 `lib_draw.paint_tones` → `tex/bolt32_ramp.png`. 자른 소재 길은 그대로 |
| 그대로 쓰는 것 | 속성마다 한 번 굽고 복사(`bake_ramp`) · color 짝 → `#FFFFFF` · 짝 tiles 가 없으면 override `textureSheet.tiles` · `ensure_inside` |

**`lib_cut.paint` 를 안 쓰는 까닭** : paint 는 휘도가 가장 가까운 램프 색을 고른다. 노랑 램프(휘도 255 · 237 · 207 · 155)에서 회색 191 은 Y2(207)로 가서 **Y1 이 사라진다.** ice 에서도 127 이 p3 로 간다. 단 번호를 그대로 옮기는 쪽이 팔레트와 상관없이 맞다.

## 4. 템플릿 `lightning_strike`

### 4-1. 층

| 층 | 소재 · 크기 | main | emission · shape | 그 밖 |
| --- | --- | --- | --- | --- |
| `bolt` | `$bolt_tex`(lib:bolt32) · `$bolt_size` 32 | lifetime 0.666 · speed 0 · color `$color` · maxParticles 1 · gravity 0 | burst [[0, 1]] · Circle r 0 · **position [0, 15]** | textureSheet fps 12 · cycles 1 · alpha · unlit · local |
| `sparks` (when `$sparks`) | `$spark_tex`(lib:dot, row random) · `$spark_size` 3 | lifetime random [`$life*0.6`, `$life`] · speed random [`$speed*0.5`, `$speed`] · color `$spark_color` · gravity `$gravity` · maxParticles 16 | burst [[0.083, `$count`]] · Cone `$spread` · rotation [-90,0,0] · position [0,0] | alpha · unlit · local |

- 두 층 모두 **alpha.** additive 는 겹친 칸이 팔레트 밖으로 나간다(1차 설계 실험 2). 그 덕에 `frame.bright` 규칙도 돌지 않는다.
- sparks 버스트 t 0.083 = 피크 장. 불씨는 「바닥에서 튐」.
- 바닥 번쩍은 소재 장 1~4 에 그려 넣었다 → 따로 층을 두지 않는다(disc · ring 층 없음).

### 4-2. params

| 이름 | 꼴 · 기본 · 범위 | 짝 · 비고 |
| --- | --- | --- |
| `color` | color · `#FFFFFF` | bolt 색. 램프 판에서는 `#FFFFFF` 로 덮인다 |
| `bolt_tex` | file · `lib:bolt32` | size `bolt_size` · color `color` |
| `bolt_size` | int · 32 · 1~64 | 32 의 정수 배. 64 는 캔버스를 넘는다 |
| `sparks` | bool · true | |
| `count` | int · 4 · 1~16 | |
| `speed` | float · 40 · 10~80 | |
| `life` | float · 0.4 · 0.1~0.5 | 0.083 + 0.5 < 0.708(마지막 장) |
| `gravity` | float · 1 · 0~3 | |
| `spread` | float · 30 · 0~60 | |
| `spark_color` | color · `p2` · fallback `color` | |
| `spark_tex` · `spark_size` | file `lib:dot` · int 3 | 짝 size |

presets 는 두지 않는다(선택 칸).

### 4-3. tiers · check

| 칸 | 값 |
| --- | --- |
| weak | `{"mul": {"count": 0.5, "speed": 0.7}}` → 불씨 2 |
| mid | `{"mul": {}}` |
| strong | `{"mul": {"count": 2, "speed": 1.3, "life": 1.2}}` → 불씨 8 · life 0.48 |
| scale | 셋 다 1. bolt 64 는 캔버스 64 를 넘는다 |
| check | `burst_only` bolt · `burst_only` sparks · `max_duration` 0.75 · `last_frame_empty`(frame) |
| 뺀 것 | `symmetric_x` — 갈래가 좌우로 비대칭이고, 1차 B1 에서 작은 면적 탓에 문턱(2)을 넘었다. 대칭은 소재 시험(2-3)과 일반 규칙 `frame.lopsided` 로 본다 |

duration 을 안 적으면 max_duration 0.75 → 9장(t 0.042~0.708). 장 1 = 소재 장 0.

### 4-4. 사전과의 관계

| 경우 | 결과 |
| --- | --- |
| × lightning | 치환 `lib:bolt32 → ramp:bolt32` → tex/ 노랑 램프 · color `#FFFFFF` · sparks p2 노랑. warn 0 이 목표 |
| × fire · ice · poison(치환 없음) | lib 회색 4단 × 사전 `color: p2` → 팔레트 밖 → frame.palette warn. 펼치기는 통과한다. 치환 한 줄씩 넣으면 그 속성 색 번개가 된다(9절) |
| 사전 없이(바탕 프로필) | 회색 × `#FFFFFF` → warn. 템플릿 desc 에 「변형 사전 램프와 함께 쓴다」고 적는다 |
| 다른 템플릿 × lightning | 「안 쓴 치환 lib:bolt32」 info 하나가 는다 |

## 6. 측정 규칙 충돌

| 규칙 | A안에서 | 피하는 법 |
| --- | --- | --- |
| `frame.bright` · `BRIGHT_WARN_RUN` 3 | **additive 층에만 돈다** → 두 층 모두 alpha 라 안 돈다. additive 로 바꿔도 W 가 있는 장은 소재 장 1 · 2 둘뿐이다(Y1 선형 휘도 0.88 < 0.98) | 층 alpha 고정(fixed) |
| `frame.last_not_empty` | bolt 0.666 · sparks 끝 ≤ 0.583 → 장 9(0.708) 빔 | life 상한 0.5 · duration 은 max_duration 기본. duration 0.6 처럼 짧게 주면 마지막 장이 불씨라 warn |
| `frame.palette` · `palette_dist` | 램프 판은 칠한 색 = 팔레트 · color 흰 → 0 | 사전 치환 한 줄. 치환 없는 판은 warn(4-4) |
| `recipe.lib_size` | 32 / 32 = 1. 램프 판은 파일 시트라 검사 밖 | tiers scale 1 |
| `frame.colors` | 장마다 ≤ 4 | 소재 장 규칙(2-3) · sparks 는 p2(이미 쓰는 색) |
