# VFXTool 7판 — 변형 묶음(variant set) 설계

> 2026-10-15 · 근거 : 사용자 요청 「같은 종류의 다양한 버전 이펙트」(권장안 확정) · 조사 결정 D1~D8 (메인 확정)
> 앞 설계 : `2026-10-15-소재묶음설계.md` · 구현 실측 : `../Research/2026-10-15-VFX툴구현실측.md`

## 0. 결론 먼저

- 템플릿 하나를 **속성(불 · 얼음 · 독 · 번개) × 세기(약 · 중 · 강) × 시드 n개**로 한 번에 펼쳐, 판마다 Unity 를 돌리고 **격자 접촉판 한 장**으로 견준다.
- AI 는 짧은 **묶음 JSON** 하나만 쓴다. 색 · 소재 · 배수는 툴의 **변형 사전**(툴 기본 + 게임 폴더 덮기)이 채운다.
- 속성은 **팔레트를 통째로 바꾼다.** 판마다 변형 폴더에 그 팔레트로 고친 `profile.json` 사본을 써서 check · measure · sheet 가 모두 그 팔레트로 판정한다.
- 세기는 **템플릿의 `tiers` 칸**(파라미터 배수 + 크기 정수 배)으로 정한다. 범위 밖 · 정수 배 아님이면 **그 판만** 「펼치기 실패」로 적고 나머지는 돈다.
- 소재를 바꾸려고 다섯 템플릿의 `texture` · `startSize` 를 **`$<층>_tex` · `$<층>_size` 파라미터**로 뺀다. 기본값이 지금 값과 같아 **골든 resolved 는 한 글자도 안 바뀐다.**
- 1차는 Unity 를 판마다 따로 띄운다(D1). 실측에서 기동 시간 비율을 재서 2차(한 번에 묶어 돌리기) 후보로만 적는다.

### 낱말 구분 — 「변형」이 둘이다

| 낱말 | 뜻 | 어디 |
| --- | --- | --- |
| 소재 **줄 변형** (`variants` 칸) | 소재 시트 PNG 한 장 안의 줄마다 다른 그림(shard 의 l2 · l3 · blob4) | 소재 메타 JSON (앞 설계 2-2) |
| **변형 묶음 (variant set)** | 이펙트 한 가지를 속성 · 세기 · 시드로 여러 판 펼친 묶음 | 이 문서. 명령 `vfxtool variant`, 사전 폴더 `vfxtool/variants/` |

문서 · 코드 · 보고에서 이 기능은 늘 「변형 묶음」· `variant set` 으로 쓴다. 메타의 `variants` 칸 이름은 그대로 둔다(계약).

## 1. 목표와 범위

게임에는 「맞음 파편」 하나가 아니라 불 · 얼음 · 독 맞음, 약 · 강 맞음이 다 필요하다. 지금은 레시피를 판마다 손으로 고쳐 고리를 돌려야 한다. 7판은 **한 번 적고 한 번 돌려 한 장으로 고르게** 한다.

| 하는 것 | 안 하는 것 (10절) |
| --- | --- |
| 변형 사전(속성 · 세기) · 묶음 JSON · 펼치기 | Unity 한 번에 여러 판 굽기 (2차 후보) |
| 판별 프로필 사본 · 램프 다시 굽기 | VFX Graph · 실시간 파라미터 프리팹 |
| `vfxtool variant expand · run · sheet` | 펼친 판을 고리(`loop`)로 자동 다듬기 — 고를 판은 사람이 고르고 `patch` 로 덧칠 |
| 격자 접촉판 · 시간 띠 | 속성별 새 템플릿(모양 자체가 다른 것) |

## 2. 사용 흐름

### 2-1. AI 가 쓰는 묶음 JSON

```json
{ "version": 1, "name": "hit", "template": "hit_sparks",
  "profile": "../profile.json", "duration": 0.6, "seed": 1000,
  "params": { "ring": true }, "preset": null,
  "attrs": ["fire", "ice"], "tiers": ["weak", "mid", "strong"], "seeds": 2 }
```

| 칸 | 뜻 | 필수 |
| --- | --- | --- |
| `name` | 묶음 이름 = 출력 폴더 이름 · 판 이름 앞머리. 안 적으면 템플릿 이름 | 아니 |
| `template` | 템플릿 이름(내장 또는 `--templates`) | 예 |
| `profile` | 바탕 프로필(묶음 파일 기준 상대 경로). 팔레트 말고 칸(ppu · fps · 캔버스 등)은 여기서 온다 | 예 |
| `duration` · `fixedTimeStep` | 레시피 꼭대기 칸 그대로. 기본 템플릿 `max_duration` 이 있으면 그 값 · `true` | 아니 |
| `seed` | 기준 시드. 기본 1 | 아니 |
| `params` · `preset` | 모든 판에 깔 템플릿 값(레시피 템플릿 층과 같은 뜻) | 아니 |
| `attrs` | 속성 이름 목록. 사전 파일 이름. `"base"` 는 「바탕 프로필 팔레트 그대로」(예약어) | 예 |
| `tiers` | 세기 이름 목록 또는 즉석 표 객체(3-3) | 예 |
| `seeds` | 시드 수 n (1 ~ 4) | 아니 (기본 1) |

판 수 = attrs × tiers × seeds. **상한 48판**(한 판 약 18초 → 15분). 넘으면 종료 2.

### 2-2. 명령

```
vfxtool variant expand hit.json --work D:/fxwork [--variants <게임 사전 폴더>]... [--templates <폴더>]... [--lib-src <원본 폴더>]
vfxtool variant run    --work D:/fxwork/hit --project <Unity 프로젝트> [--only <판 이름>]... [--unity …] [--timeout …]
vfxtool variant sheet  --work D:/fxwork/hit
```

`expand` 는 Unity 없이 끝난다(펼치기 + check). `run` 은 남은 판을 차례로 돌리고 끝에 `sheet` 를 부른다.

### 2-3. 산출물 폴더

```
D:/fxwork/hit/
├─ set.json                      ← 장부 : 묶음 원본 · 판 목록 · 판별 상태 · 시간
├─ overview.png                  ← 격자 접촉판 (8절)
├─ strips_1.png                  ← 시간 띠 (판 12개씩 한 장)
├─ hit_fire_weak_s0/
│  ├─ recipe.json                ← 펼치기 전 템플릿 층 레시피 (사람이 patch 로 덧칠할 원본)
│  ├─ profile.json               ← 속성 팔레트로 바꾼 프로필 사본
│  ├─ tex/                       ← 램프 PNG · 복사한 게임 파일 텍스처 (있을 때만)
│  └─ resolved.json · frames/ · result.json · measure.json · sheet.png · anim.gif   ← run 뒤
├─ hit_fire_weak_s1/ …
└─ hit_ice_strong_s1/
```

변형 폴더 하나는 **고리 바퀴 폴더와 같은 꼴**이라 `measure` · `sheet` · `gif` 를 그대로 쓴다.

### 2-4. 사람이 보는 것

`overview.png` 한 장에서 줄(속성) × 열(세기 · 시드)로 고른다. 고른 판은 그 폴더의 `recipe.json` 을 게임 저장소로 가져가 기존 `patch` · `loop` 로 다듬는다.

## 3. 변형 사전

### 3-1. 자리와 덮기

```
VFXTool/src/vfxtool/variants/      ← 데이터만 (py 없음, lib/ 와 같은 까닭)
├─ fire.json · ice.json · poison.json · lightning.json
```

- 게임 쪽은 `--variants <폴더>` (여러 번). **템플릿과 같은 「내장 < 뒤에 준 폴더」 규칙** — 같은 이름이면 파일 통째로 바뀐다(칸 단위 합치기 없음). 합치기를 안 하는 까닭 : 팔레트 반만 바뀐 사전은 사람이 알아보기 어렵다.
- 폴더 바로 아래 `*.json` 만 읽는다. 파일 이름(확장자 뺀 것) = 속성 이름 = 안의 `name`. 다르면 VfxError(종료 2).
- `pyproject.toml` package-data 에 `variants/*.json` 을 더한다.

### 3-2. 속성 사전 꼴

```json
{ "version": 1, "name": "fire", "title": "불",
  "palette": ["#FFF4A3", "#FFC23D", "#F2751A", "#C2321F", "#5E1914"],
  "materials": { "lib:shard": "lib:dot" },
  "ramp": ["p0", "p1", "p2", "p3"] }
```

| 칸 | 뜻 | 검사 |
| --- | --- | --- |
| `palette` | 바탕 프로필 `palette` 를 **통째로** 바꿀 색. 밝은 것 → 어두운 것 순(p0 = 주색, 템플릿 관례와 같음) | hex 1 ~ 32개 (`profile/common` 의 `_hex_list` 재사용) |
| `max_colors` · `fx_extra` | 있으면 프로필 그 칸도 바꾼다. 없으면 바탕 값 | 같은 함수 |
| `materials` | 소재 치환표 `{바꿀 소재: 새 소재}`. 템플릿 층의 `$<층>_tex` 기본값이 왼쪽과 같으면 바꾼다 | 4-4 |
| `ramp` | 램프 색(팔레트 번호). 치환표 오른쪽에 `ramp:<소재>` 가 있을 때만 쓴다 | 번호가 새 팔레트 안 |

모르는 칸은 VfxError(종료 2). 프로필 읽기가 모르는 칸을 무시하는 것과 달리, 사전은 사람이 손으로 쓰는 작은 파일이라 오타를 바로 알린다.

### 3-3. 세기 표 — 템플릿의 새 칸 `tiers`

세기는 템플릿마다 다르게 걸려야 한다(파편 수 · 먼지 폭 · 반짝 밀도). 그래서 속성 사전이 아니라 **템플릿 파일 안**에 둔다. `presets` 를 넓히지 않고 새 칸을 둔 까닭 : preset 은 **값을 박는다**(count = 12). 세기는 게임이 고른 값 위에 **곱한다** — 게임이 count 10 을 깔고 strong 을 고르면 20 이 돼야 한다.

```json
"tiers": {
  "weak":   { "mul": { "count": 0.5, "speed": 0.7, "life": 0.8 } },
  "mid":    { "mul": {} },
  "strong": { "mul": { "count": 2, "speed": 1.3, "life": 1.2 }, "scale": 1 }
}
```

- `mul` : 템플릿 파라미터 이름 → 배수. int · float 파라미터만. 바탕 값(뼈대 < preset < 묶음 params)에 곱한다. int 는 **반올림**(0.5 는 올림)한다. float 은 `values.DIGITS` 자리로 반올림한다(0.5 × 1.2 가 0.6000000000000001 이 돼 `max 0.6` 에 걸리지 않게).
- `scale` : 크기 정수 배(기본 1). 모든 `*_size` 짝 파라미터(5절)에 곱한다. 바탕이 소재 칸이니 곱해도 늘 칸의 정수 배다.
- `mid` 는 **빈 배수**로 둔다 — 중 = 템플릿 기본 그대로라 골든 · 기존 레시피와 바로 견줄 수 있다.
- 묶음 `tiers` 에 즉석 객체 `{"name": "huge", "mul": {…}, "scale": 2}` 를 섞어도 된다(게임이 템플릿을 복사하지 않고 한 판만 더 볼 때).
- `template.py` `TEMPLATE_KEYS` 에 `tiers` 를 더하고, `_read_template` 이 꼴(배수 > 0 · 파라미터 있음 · 숫자 꼴 · scale 1 이상 정수)을 본다. 틀리면 템플릿 파일 오류(종료 2).

### 3-4. 기본 사전 — 네 속성 팔레트 (제안)

도트 이펙트에서 흔히 쓰는 **색상 밀기(hue shift)** 를 따랐다 — 밝은 단은 따뜻한 노랑 쪽, 어두운 단은 차가운 남 · 보라 쪽으로 민다. 단마다 명도를 크게 벌려(대략 휘도 0.9 → 0.15) 64 캔버스에서도 단이 읽히게 했다. 다섯 색인 까닭 : 템플릿이 p0 ~ p3 을 쓰고(hit_sparks smoke p3), 하나는 램프 · 게임 덮기 여유다. **값은 제안이다 — 실측 접촉판을 보고 사람이 고친다.**

| 속성 | p0 | p1 | p2 | p3 | p4 | 소재 치환 |
| --- | --- | --- | --- | --- | --- | --- |
| `fire` 불 | `#FFF4A3` | `#FFC23D` | `#F2751A` | `#C2321F` | `#5E1914` | shard → dot (불티) |
| `ice` 얼음 | `#F2FBFF` | `#A8E6FF` | `#5CB8F2` | `#2F6DC4` | `#1C2E6B` | shard → cross (결정 반짝) |
| `poison` 독 | `#E6FF8A` | `#8CD94A` | `#3E9E46` | `#6A2E8C` | `#2E1446` | shard → dot (거품) · 어두운 단은 보라(독 연기) |
| `lightning` 번개 | `#FFFDE0` | `#FFF04D` | `#B8E0FF` | `#6C7CFF` | `#2B2A73` | shard → streak · ring → star4 |

- `ramp` 는 네 사전 모두 `["p0", "p1", "p2", "p3"]` 로 두지만, 기본 사전의 치환표에는 `ramp:` 를 **넣지 않는다**(hit_sparks core 가 기본 꺼짐, 원본 PNG 가 저장소에 없음). 게임이 쓸 때 덮기 사전에서 `"lib:burst16": "ramp:burst16"` 를 더한다(6-2).
- p0 은 흰색이 아니다. 흰 번쩍(flash)은 `#FFFFFF` 고정이고 프로필 `fx_extra` 가 받는다 — 흰색을 팔레트에 또 넣으면 `max_colors` 만 먹는다.

### 3-5. 기본 세기 표 — 다섯 템플릿

| 템플릿 | weak | mid | strong | 걸리는 상한 (strong 기준) |
| --- | --- | --- | --- | --- |
| hit_sparks | count ×0.5 · speed ×0.7 · life ×0.8 | — | count ×2 · speed ×1.3 · life ×1.2 | count 12 ≤ 48 · life 0.6 ≤ 0.6 (꽉 참) · speed 117 ≤ 200 |
| land_dust | count ×0.5 · width ×0.67 · rise ×0.67 | — | count ×1.5 · width ×1.67 · rise ×1.67 | count 3 ≤ 4 · width 10 ≤ 24 |
| ambient_motes | density ×0.5 · drift ×0.67 | — | density ×2 · drift ×1.5 | `coverage_max 5%` (measure) |
| heal_rise | count ×0.5 · radius ×0.67 · rise ×0.75 | — | count ×2 · radius ×1.5 · rise ×1.5 | count 24 ≤ 40 · rise 30 ≤ 60 |
| sparkle | count ×0.5 · radius ×0.7 | — | count ×2 · radius ×1.4 | count 12 ≤ 30 |

- 기본 `scale` 은 모두 1이다. 64 캔버스에서 16칸 소재를 ×2 하면 캔버스 반을 덮는다. 큰 판은 게임이 즉석 세기로 연다.
- sparkle 의 `life` 는 star4 플립북 한 생(4장 ÷ 12)이라 **곱하지 않는다** — 곱하면 `recipe.flipbook_life` 에 걸린다.
- 배수는 지금 `presets` 의 small · big 값과 가깝게 잡았다(hit_sparks big = count 12 · speed 120 · life 0.6).

## 4. 펼치기 규칙

### 4-1. 판 하나 만드는 순서

```
묶음 + 사전 + 템플릿
 → (1) 이름 · 시드 정하기
 → (2) 프로필 사본 view (바탕 프로필 + 속성 palette · max_colors · fx_extra)
 → (3) 파라미터 : 템플릿 기본 < preset < 묶음 params  → 세기 mul · scale → 소재 치환
 → (4) 레시피 한 장 (템플릿 층 하나) 쓰기
 → (5) run_check(레시피, 사본 프로필) — 지금 check 그대로, Unity 없음
 → 통과면 상태 expanded, 아니면 failed + 까닭
```

(5)에서 지금 check 를 그대로 돌리므로 **새 규칙을 따로 만들지 않는다.** `recipe.lib_size`(정수 배) · params 범위 · `max_duration` · `recipe.flipbook_life` · 층 상한 6 · 팔레트 번호 밖(`recipe.palette`) · fps 범위가 모두 여기서 걸린다. 펼치기 자체가 막는 것만 `variant.*` 규칙으로 따로 둔다(4-5).

### 4-2. 이름

- 꼴 `<묶음 name>_<속성>_<세기>` + 시드가 둘 이상이면 `_s<k>` (k = 0부터). 예 `hit_fire_strong_s1`.
- 글자 `[a-z0-9_]` 만. 묶음 name · 속성 · 세기 이름이 이미 그 꼴이어야 한다(아니면 종료 2 — 판 하나가 아니라 묶음이 틀렸다).
- **40자 상한**(층 이름 상한과 같게). 넘는 판만 `variant.name` 으로 실패. 묶음 `name` 을 짧게 주면 풀린다 — 그래서 묶음 name 이 따로 있다.
- 이름이 겹치면(즉석 세기 이름이 기본과 같음 등) 종료 2.

### 4-3. 시드

- 판 k 의 시드 = `seed + k × 16` (k = 0 ~ n−1). 속성 · 세기가 달라도 **같은 k 는 같은 시드** — 그래야 줄끼리 견줄 때 「색만 다르다」가 보인다.
- 16 간격인 까닭 : C# 이 층마다 `seed + 층 번호` 를 쓴다(층 상한 6). 1 간격이면 이웃 판 층끼리 같은 난수를 받는다(mem 20261015-05054c83).
- 시드 상한 : `seed + (n−1) × 16` 이 schema 의 int 범위 안. 밖이면 종료 2.

### 4-4. 소재 치환

1. 템플릿의 file 파라미터 중 `size` 짝이 있는 것(5절)만 대상이다. 그 파라미터의 **지금 값**(기본 또는 묶음 params)이 치환표 왼쪽과 같으면 오른쪽으로 바꾼다.
2. 오른쪽이 `lib:` 면 `material_lib.load` 로 메타를 읽어 **`kind` 와 `tiles` 가 왼쪽과 같아야** 한다. 다르면 `variant.material` 실패. 까닭 : 낱알 ↔ 플립북을 바꾸면 수명 · `textureSheet` 칸이 다 틀어지고, 줄 수가 다르면 `row` 가 범위 밖이 된다.
3. 짝 `size` 파라미터 = 새 소재 `cell` × 세기 `scale`. sparkle 처럼 `tiles` 짝이 있으면 메타 `tiles` 로 같이 바꾼다.
4. 오른쪽이 `ramp:<소재>` 면 6-2 의 램프 굽기 대상이다. 굽고 나면 파라미터 값 = 변형 폴더 `tex/<소재>_ramp.png` 상대 경로, `color` 짝 파라미터 = `"#FFFFFF"`.
5. 치환표에 있는데 이 템플릿이 안 쓰는 소재는 그냥 넘어간다(속성 사전은 모든 템플릿에 걸리니까). 보고의 판 `notes` 에 「안 쓴 치환 lib:ring」 info 만 남긴다.

### 4-5. 펼치기 실패 표시

| 규칙 | 언제 | 처리 |
| --- | --- | --- |
| `variant.name` | 이름 40자 넘음 | 그 판 failed |
| `variant.palette_short` | 레시피가 쓰는 가장 큰 `p<n>` ≥ 속성 팔레트 길이 (fallback 적용 뒤) | 그 판 failed |
| `variant.tier_range` | 배수 뒤 값이 파라미터 min · max 밖 (자르지 않는다) | 그 판 failed |
| `variant.material` | 모르는 소재 · kind · tiles 다름 | 그 판 failed |
| `variant.ramp_source` | `ramp:` 인데 `--lib-src` 없음 · 원본 sha256 다름 · 램프 번호가 팔레트 밖 | 그 판 failed |
| `variant.check` | (5) check 에서 error | 그 판 failed, check issues 를 그대로 붙임 |
| — | 묶음 꼴 · 모르는 속성 · 모르는 템플릿 · 판 수 48 초과 · 이름 겹침 | 종료 2, 아무것도 안 씀 |

- **값을 범위 안으로 자르지 않는다.** 잘라 버리면 strong 과 mid 가 같은 판이 되는데 사람은 모른다. 실패로 보여 주고 즉석 세기로 고치게 한다.
- 실패한 판도 폴더와 `recipe.json` 은 만든다(무엇이 틀렸는지 열어 보게). `set.json` 에 `"state": "failed"` · `issues` 를 적고 `run` 이 건너뛴다.

## 5. 템플릿 손질 — `$tex` · `$size` 파라미터

다섯 템플릿의 시트 층마다 `texture` · `main.startSize` 를 파라미터로 뺀다. sparkle 의 `sheet` · `size` · `tiles` 가 이미 이 꼴이라 그 선례를 넓힌다.

```json
"texture": "$sparks_tex",
"main": { "startSize": "$sparks_size", … }

"sparks_tex":  { "type": "file", "default": "lib:shard", "size": "sparks_size", "desc": "파편 소재" },
"sparks_size": { "type": "int",  "default": 5, "min": 1, "max": 64, "desc": "파편 크기(텍셀). 소재 칸의 정수 배" }
```

- file 파라미터 spec 에 새 키 셋 : `size`(짝 int 파라미터 이름, 필수) · `tiles`(짝 tiles 파라미터, 있을 때만) · `color`(램프 때 흰색으로 바꿀 색 파라미터, 있을 때만). `_read_template` 이 짝이 있고 꼴이 맞는지 본다(`_check_fallbacks` 옆에 `_check_pairs`).
- 층 이름을 머리로 쓴다(`flash_tex` · `ring_size`). 좌우 짝 층(land_dust `puff_l` · `puff_r`)은 **한 쌍**을 같이 쓴다(`puff_tex` · `puff_size`) — 좌우 소재가 갈리면 `symmetric_x` 가 깨진다.

| 템플릿 | 새 파라미터 (기본값) |
| --- | --- |
| hit_sparks | `flash_tex` disc / `flash_size` 7 · `core_tex` burst16 / `core_size` 16 / color `core_color` · `ring_tex` ring / `ring_size` 15 / color `color` · `sparks_tex` shard / `sparks_size` 5 · `smoke_tex` puff8 / `smoke_size` 8 / color `smoke_color` |
| land_dust | `puff_tex` puff16 / 16 · `small_tex` dot / 3 · `chips_tex` shard / 5 (좌우 공용) |
| ambient_motes | `motes_tex` dot / 3 · `glint_tex` star4 / 7 |
| heal_rise | `dots_tex` cross / 5 · `glow_tex` ring / 15 / color `glow_color` · `streak_tex` streak / 7 · `rest_tex` dot / 3 |
| sparkle | 기존 `sheet` 에 짝 키(`size` · `tiles`)만 더함 · `mote_tex` dot / 3 · `glow_tex` disc / 7 |

**골든 불변 조건** : 다섯 템플릿의 `Test/data/golden/*.resolved.json` 이 손질 전과 **바이트까지 같아야** 한다. `$sparks_size` 가 int 5 로 풀리고(정수 파라미터는 int 그대로 — `_param_ref`), `$sparks_tex` 가 `lib:shard` 로 풀린 뒤 지금처럼 절대 경로가 된다. resolved 에는 파라미터 표가 안 실리므로 파라미터를 더해도 바뀌지 않는다. 시험은 골든을 **다시 만들지 않고** 그대로 견준다 — 다시 만들면 이 조건이 안 지켜져도 지나간다.

- 손질은 기존 레시피를 안 깬다 : 새 파라미터는 모두 기본값이 있고, override 로 `texture` 를 덮던 레시피도 override 가 파라미터 뒤에 겹치므로 그대로 이긴다.
- `fixed` 에 `texture` · `startSize` 를 넣지 않는다(지금도 없다).
- `template show` 출력 · `vfxtool-usage` 스킬의 파라미터 표가 길어진다 — 스킬 문서도 같이 고친다.

## 6. 판별 프로필 사본 · 램프 굽기

### 6-1. 프로필 사본

- 바탕 프로필 **원본 JSON**(view 가 아니라 파일 내용)을 읽어 `palette`(· `max_colors` · `fx_extra`)만 바꿔 `<판>/profile.json` 에 쓴다. 원본의 `{"value", "source"}` 꼴 · 모르는 칸은 손대지 않고 그대로 옮긴다 — 사본이 바탕과 「팔레트만 다르다」는 게 diff 로 보이게.
- `base` 속성이면 원본을 그대로 복사한다.
- 판 레시피의 `profile` 칸 = `"profile.json"`(같은 폴더). 그래서 check · measure · sheet 가 따로 인자 없이 사본으로 판정한다. 고리와 같은 `settings` 를 만들 때 `profile_override = False` · `profile` = 사본 절대 경로.
- `max_colors` 가 새 팔레트보다 크면 둔다. 작으면 바꾸지 않고 measure 의 `frame.colors` 가 알리게 둔다(사전에 `max_colors` 를 적으면 된다).

### 6-2. 램프 굽기 — 램프 소재를 쓰는 판만

앞 6판에서 burst16 은 흰 실루엣이면 원판으로 죽고, `lib cut --ramp` 로 원본 명도를 팔레트 색으로 미리 칠한 PNG 가 낫다고 정했다(mem 20261015-4f2f6700). 팔레트가 판마다 바뀌니 **램프도 판마다 다시 굽는다.**

```
펼치기 (3) 에서 치환 결과가 ramp:burst16 인 파라미터를 만나면
 → 사본 팔레트로 사전 ramp 번호(p0 ~ p3)를 hex 로 푼다
 → lib_cut.cut_ramp(<--lib-src>/<sources.json 의 원본 파일 이름>, "burst16", <판>/tex, hex 목록)
     (원본 sha256 검사 · 잘림 검사 · lib/ 안 쓰기 거절은 cut_ramp 가 이미 한다)
 → 파라미터 = "tex/burst16_ramp.png", color 짝 = "#FFFFFF"
```

- 템플릿 기본 · 기본 사전에는 `ramp:` 가 없어서 **기본 흐름에서는 굽기가 한 번도 안 돈다.** 게임이 덮기 사전으로 켤 때만 돈다.
- 같은 속성 · 같은 램프면 결과가 같으니 묶음 안에서 한 번 굽고 판 폴더로 복사한다(속성마다 1회).
- 원본은 저장소에 없다(앞 설계 3-2). `--lib-src` 를 안 주면 그 판들만 `variant.ramp_source` 로 실패한다.

### 6-3. 게임 파일 텍스처

묶음 `params` 가 게임 쪽 파일 텍스처(예 sparkle `sheet`)를 주면 `<판>/tex/` 로 **복사**한다. 판 폴더 하나가 check 의 `input_root` 가 되어 경로 감옥이 한 겹으로 끝난다. PNG 만 · 4MB 상한 · 원본은 묶음 폴더(또는 `--input-root`) 안이어야 한다.

## 7. 명령 설계 — `vfxtool variant`

| 동작 | 인자 | 하는 일 |
| --- | --- | --- |
| `expand <묶음.json>` | `--work`(필수) · `--variants`(여러 번) · `--templates`(여러 번) · `--lib-src` · `--input-root` · `--force` | `<work>/<name>/` 에 판 폴더 · `set.json` 을 쓴다. 폴더가 이미 있으면 거절(`--force` 면 판 폴더를 지우지 않고 **실패 · 남은 판만** 다시 씀) |
| `run` | `--work`(묶음 폴더) · `--project`(필수) · `--only`(여러 번) · `--unity` · `--timeout` · `--save-root` · `--no-sheet` | `expanded` 판을 이름 순으로 하나씩 `run_pipeline`. 끝나면 `sheet`. 이미 `done` 인 판은 건너뛴다(끊겨도 다시 부르면 이어 돈다) |
| `sheet` | `--work` | `overview.png` · `strips_N.png` 다시 그림 |

- `run` 은 `set.json` 옆에 잠금 파일을 둔다(`loop_state.locked` 와 같은 수법). 같은 Unity 프로젝트를 둘이 못 쓰는 제약(D1)과 맞춘다.
- Unity 프리팹 이름 = 판 이름. 저장 자리는 기존 `--save-root` 그대로라 판마다 다른 프리팹이 생긴다.

### 7-1. 보고 JSON 꼴 (stdout, 기존 `report.build` 꼴)

```json
{ "status": "fail",
  "issues": [ { "rule": "variant.tier_range", "severity": "error", "variant": "hit_ice_strong_s0",
                "detail": "params.life 0.72 — 0.6 이하여야 한다" } ],
  "metrics": {
    "set": "D:/fxwork/hit/set.json",
    "counts": { "total": 12, "expanded": 10, "failed": 2, "done": 0 },
    "variants": [ { "name": "hit_fire_weak_s0", "attr": "fire", "tier": "weak", "seed": 1000,
                    "state": "done", "errors": 0, "warns": 1,
                    "seconds": { "wall": 21.4, "unity_build": 1.2, "unity_render": 3.1 } } ],
    "timing": { "wall_total": 251.0, "unity_inside": 51.6, "startup_ratio": 0.79 },
    "next": "variant sheet" } }
```

- 판 issue 에는 `variant` 칸을 더한다(어느 판 것인지). 판 안의 render · measure issue 는 `set.json` 과 판 폴더 `measure.json` 에만 두고 보고에는 수만 싣는다 — 48판의 issue 를 다 실으면 보고가 너무 길다.
- `timing.startup_ratio` = 1 − (Unity 안 build + render 초 합 ÷ 벽시계 합). **0.5 를 넘으면 info `variant.startup_heavy`** 로 「Unity 묶어 돌리기(2차)가 값어치 있다」를 남긴다(D1).

### 7-2. 종료 코드

| 코드 | 뜻 |
| --- | --- |
| 0 | 모든 판이 expanded(expand) · done(run). warn 은 있어도 0 (기존 `EXIT_CODES` 와 같음) |
| 1 | 판 하나 이상 failed · render 실패 |
| 2 | 묶음 · 사전 · 인자 · 폴더 오류. 아무 판도 안 만들거나 안 돌림 |

## 8. 격자 접촉판

### 8-1. `overview.png`

```
+--------------------------------------------------------------+
| hit | hit_sparks | seed 1000 +16k | 12 variants | fail 2      |   ← 머리글 (ASCII)
+--------+-----------+-----------+-----------+-----------+-----+
|        | weak s0   | weak s1   | mid s0    | mid s1    | …   |   ← 열 머리
| fire   | [칸]      | [칸]      | [칸]      | [칸]      |     |
|        | #5 e0 w1  | #4 e0 w0  | …                           |   ← 칸 밑 : 고른 장 · error · warn
| ice    | [칸]      | [FAIL]    | …                           |
+--------+-----------+-----------+-----------+-----------+-----+
```

- 줄 = 속성(묶음 `attrs` 순), 열 = 세기 × 시드(세기 순 안에서 시드 순).
- 칸 그림 = 그 판에서 **덮은 면적이 가장 큰 장** 하나. `measure.json` 의 `metrics.coverage` 목록에서 고르고, 같으면 앞 장. 이펙트가 가장 크게 퍼진 순간이 속성 · 세기 차이를 가장 잘 보여 준다.
- 칸 크기 = 캔버스 텍셀 × `frames.cell_scale`(sheet.py 와 같은 배율), 검은 바탕 합성(`sheet.composite`)만. 흰 바탕 줄은 판별 `sheet.png` 에 이미 있다.
- 실패 판 칸 = 짙은 회색 + 마젠타 X + `FAIL <규칙 줄인 말>`. 아직 안 돈 판 = 회색 + `--`.
- 왼쪽 열 폭 = 속성 이름 최대 길이 × 6px(기본 글꼴) + 여백. 이름은 이미 ASCII 라 `header_text` 의 `?` 바꾸기는 안전장치로만 쓴다.

### 8-2. 시간 띠 `strips_N.png`

- 판 하나 = 한 줄 : 왼쪽에 판 이름(ASCII) · 그 뒤로 모든 장을 검은 바탕으로 가로로. 장 위 라벨은 첫 줄에만 `#i t=` 로 단다(줄마다 같으니까).
- 한 장에 판 12줄. 넘으면 `strips_2.png` …. 48판이면 넉 장.
- 장 하나가 32장(0.6초 × fps 등) 을 넘으면 띠가 너무 길어지니 **장을 건너 찍지 않고** 줄을 접는다(sheet 의 `PER_GROUP` 12 와 같은 접기).

### 8-3. 재사용

`sheet.py` 의 `composite` · `_enlarge` · `frames.load_round` · `load_frames` · `to_texels` 를 그대로 쓴다. 새 파일 `variant_sheet.py` 는 배치(격자 좌표)만 한다. `_enlarge` 는 밑줄 함수라 `enlarge` 로 이름을 열어 준다(호출 한 군데 바뀜).

## 11. 보안 — 경로 · 글자 · 쓰기 자리

기존 잣대(`paths.ensure_inside` · `normalize_save_root` · C# `CheckedAssetPath`)를 그대로 쓰고 새 구멍만 막는다. `security-invariants` 스킬 기준으로 점검한다.

| 들어오는 것 | 막는 것 |
| --- | --- |
| 속성 · 세기 · 묶음 이름 | `^[a-z0-9_]{1,16}$`(묶음 name 은 24). 파일 이름으로 바로 쓰므로 `/` · `..` · 드라이브 글자가 들어갈 틈이 없다. 속성 이름 → 파일은 **읽어 둔 사전 표에서 찾기만** 하고 경로를 이어 붙이지 않는다 |
| `--variants` · `--templates` · `--lib-src` 폴더 | 있어야 함 · 바로 아래 `*.json`(`lib-src` 는 sources.json 에 적힌 파일 이름만) · 심볼릭 링크 · junction 거절(`_reject_symlinks`) |
| 묶음 `profile` · 게임 파일 텍스처 | `ensure_inside(<묶음 폴더 또는 --input-root>)` |
| 쓰기 — 판 폴더 · `profile.json` 사본 · `tex/` | 모두 `ensure_inside(<work>/<name>)`. `--work` 는 Unity 프로젝트 밖이어야 한다(loop 와 같은 검사) |
| 램프 출력 | `cut_ramp` 가 이미 lib/ 안 쓰기를 거절. 출력 자리는 판 `tex/` 로 고정 |
| 프리팹 저장 | `--save-root` → `normalize_save_root`(Assets/ 안) · 이름은 판 이름(위 글자 규칙) |
| JSON 크기 | 묶음 · 사전은 64KB 상한(`read_json` 앞에서 파일 크기 확인) — 사람이 쓰는 작은 파일이다 |
| `--force` | 판 폴더를 지우지 않는다. 덮어쓰기는 `set.json` 에 적힌 판 폴더 안 파일만 |
| 파생 그림 `strips_N.png` | 예외로 자동 지운다 — 묶음 폴더 바로 아래 · 이름 꼴 `strips_<숫자>.png` · 보통 파일(링크 아님)만. 판 수가 줄면 옛 띠가 남아 사람이 속기 때문이다 |
