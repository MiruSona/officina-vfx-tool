# VFXTool 설계 — 레시피 JSON 으로 Shuriken 이펙트를 조립·렌더·검수하는 고리 (2026-10-14)

**한 줄 요약** : AI 는 짧은 레시피 JSON(또는 템플릿 + 파라미터)만 쓴다. Python `vfxtool` 이 프로필·템플릿을 펼쳐 검사하고, C# UPM `com.officina.vfx` 가 `-batchmode` 에서 ParticleSystem 프리팹을 조립해 투명 배경 프레임 PNG(RGBA) 를 뽑는다.
Python 이 프레임을 재서 접촉판 한 장과 `{status, issues, metrics}` 를 돌려주면, AI 는 부분 덮기 patch 로 고친다. 최대 4바퀴, 최고점 판을 돌려준다.

앞 문서 : `../Research/2026-10-14-VFX툴조사.md`(조사) · `../Research/2026-10-14-VFX툴실측.md`(실측). 이 설계는 실측 3절 표 14줄을 그대로 전제로 쓴다. 고리 꼴은 ArtTool 의 draw 고리 설계(그리기 → 읽기 → 린트 → 고치기, 3바퀴)를, 템플릿 개념은 ArtTool 6판 설계(뼈대 · fixed · presets · check)를 **글로만** 따른다. 코드·경로는 안 가져온다.

## 1. 전체 그림

### 1-1. 고리 한 바퀴

```
[AI]     레시피 JSON (템플릿 + params, 또는 층 직접). 바퀴 2부터는 patch.json 만
[Python] check   : 템플릿 펼치기 → 프로필 값 채우기 → 텍셀을 Unity 단위로 → resolved.json + recipe.* 검사 (error 면 여기서 돌려줌)
[Python] render  : job.json → Unity.exe -batchmode -executeMethod Officina.Vfx.Editor.VfxEntry.Run
[Unity]  VfxBuilder  : resolved.json → 층마다 ParticleSystem → 머티리얼 · 텍스처 · 프리팹 에셋
         VfxRenderer : 빈 씬 · 정사영 카메라 · 프레임마다 Simulate(t_i) → 투명 배경 (0,0,0,0) 1회 렌더 → RGBA PNG
         result.json (프레임 · 입자 수 · 못 옮긴 칸) → Exit(0|1|2)
[Python] measure : 지표 + frame.* 검사 + 증상표 힌트 → measure.json  /  sheet : 접촉판 sheet.png
[AI]     sheet.png 를 Read · measure.json 을 읽음 → critic.json(점수 0~1 · 증상 낱말) → 증상표로 원인 고르기 → patch.json
[Python] loop next : 순위 비교 → rollback 여부 → 다음 바퀴 레시피 = 최고점 판 + patch
```

### 1-2. 누가 무엇을 맡나

| 일 | Python `vfxtool` | C# `com.officina.vfx` | AI |
| --- | --- | --- | --- |
| 레시피 쓰기 · 의미 점수 · 증상 고르기 · patch | — | — | ○ (짧은 JSON 만) |
| 스키마 검사 · 오타 이름 제안 | ○ | 한 번 더(방어) | — |
| 템플릿 펼치기 · 프로필 채우기 · 단위 · from/to/ease 를 곡선으로 | ○ | — | — |
| 프로필 뽑기 · 덮기 | ○ | — | 손 덮기 값 |
| ParticleSystem 조립 · 에셋 · 프리팹 · 프레임 PNG | — | ○ | — |
| Unity 찾기 · 잠금 · 타임아웃 | ○ | 종료 코드만 | — |
| 프레임 지표 · 검사 · 접촉판 · 바퀴 장부 · rollback | ○ | — | — |

**까닭** : C# 은 「resolved.json 을 Unity 객체로 그대로 옮기는」 바보 조립기로 둔다. 판단이 들어가는 일(펼치기 · 검사 · 측정)은 pytest 로 빨리 시험되는 Python 에 모은다. Unity 한 판은 약 20초라 비싸다. `vfxtool loop` 는 AI 를 부르지 않고 바퀴 폴더 · 장부 · rollback · 멈춤 판정만 맡는다.

## 2. 레시피 JSON

### 2-1. 최상위

| 칸 | 꼴 | 필수 | 뜻 |
| --- | --- | --- | --- |
| `version` · `name` · `profile` | 1 · `[a-z0-9_]+` · 경로 | ○ | 레시피 판(모르면 거절) · 이펙트 = 프리팹 · 폴더 이름 · VFX 프로필(3절, 레시피 기준 상대 경로. 레시피 폴더 밖이면 `--input-root` 필요) |
| `seed` · `fixedTimeStep` | 정수 · bool | ○ | 층마다 `randomSeed = seed + 층 번호` · `Simulate` 넷째 인자(바꾸면 그림이 달라짐, 실측 B) |
| `duration` · `fps` | 초 · 정수 | ○ · — | 이펙트 길이(층 `main.duration` 기본) · 판정 렌더 fps(없으면 프로필) |
| `loop` | bool | — | 기본 false. true 면 한 바퀴 돈 뒤부터 뽑는다(6-2) |
| `canvas` | `{texels:[w,h], scale}` | — | 판정 화면 텍셀 크기 · 텍셀당 픽셀. 기본 `[64,64]` · 4 |
| `bloom` · `light` | bool · `none`/`global` | — | 블룸(1차는 받기만, 10절) · 검수 장면 2D 빛(lit 층이 있으면 `global`) |
| `layers[]` | 층 배열 | ○ | 1~6 개(템플릿을 펼친 뒤 기준) |

### 2-2. 층

| 칸 | 꼴 | 뜻 |
| --- | --- | --- |
| `name` | 이름 | 자식 GameObject 이름. 레시피 안에서 겹치면 안 됨. `[A-Za-z0-9_][A-Za-z0-9_.\-]*` · 40자 이하 · `..` · 끝 점 · Windows 예약 이름(첫 점 앞 조각 포함) 금지 — Python 과 C# 이 같은 규칙 |
| `template` · `params` · `preset` · `override` | 4절 | 템플릿 층을 부른다. 펼치면 템플릿의 층들이 된다 |
| `material` · `blend` | `unlit`/`lit` · `alpha`/`additive` | 셰이더 갈래 · 블렌드. `lit` + `additive` 는 거절 |
| `texture` | `px1` · `px2` · 파일 경로 | 기본 `px1`(흰 1×1). 파일이면 시트 PNG(ArtTool 산출물) |
| `sortOrder` · `space` · `offset` | 정수 · `local`/`world` · `[x, y]` 텍셀 | `sortingOrder`(정렬 층은 프로필) · `simulationSpace` · 자식 위치 |
| 모듈들 | 2-3 | 적은 모듈만 켠다. 안 적은 모듈은 끔 |

**단위** : 크기 · 거리 · 속도는 **텍셀**(속도는 텍셀/초), 시간은 초, 각도는 도. `check` 가 프로필 PPU 로 나눠 Unity 단위로 바꾼다(`noise.strength` 도 길이 단위). 각도가 어떻게 넘어가나는 2-3 표 「(각도)」 줄. C# 은 단위를 모른다.

### 2-3. 모듈

| 1차 모듈 | 받는 칸 |
| --- | --- |
| `main` | `startDelay` · `startLifetime` · `startSpeed` · `startSize` · `startColor` · `gravityModifier` · `maxParticles` · `startRotation` |
| `emission` | `rateOverTime` · `bursts` (`[[t, n]]` 또는 `{t, n, cycles, interval}`) |
| `shape` | `type`(Circle · Cone · Box · Edge · Sphere) · `radius` · `angle` · `arc` · `box` · `position` · `rotation` · `radiusThickness` |
| `velocityOverLifetime` | `x` · `y` · `radial` · `orbitalZ` · `space` |
| `colorOverLifetime` · `sizeOverLifetime` · `rotationOverLifetime` | `color`(색 값 2-5) · `size`(배수 곡선) · `z`(도/초, 프로필이 막으면 error) |
| `noise` | `strength` · `frequency` · `scrollSpeed` · `octaves` · `quality` |
| `textureSheet` | `tiles:[x,y]` · `fps` · `startFrame` · `cycles` (Time Mode = FPS, Frame Blending 끔 고정). `startFrame` 은 칸 번호 — 칸 = floor(값), 모든 칸에서 고르려면 `{"random": [0, 칸 수]}` (C# 이 칸 수로 나눠 Unity 의 0~1 비율로 바꾼다) |
| (각도) | 레시피는 도. resolved 는 `main.startRotation` · `rotationOverLifetime.z` 만 라디안, shape 의 `angle` · `arc` · `rotation` 은 도 그대로 |
| (방향) | Cone 은 로컬 +Z 로 쏜다 → 위로 쏘려면 `shape.rotation: [-90, 0, 0]`. Edge 는 회전 없이 X 축 가로선 · +Y 로 나간다. Box 의 startSpeed 는 +Z 라 2D 에서 안 보인다(velocityOverLifetime 로 움직인다) |
| `renderer` | `renderMode`(Billboard 만). 머티리얼 · 정렬 · Custom Vertex Streams 는 층 칸과 코드가 정한다 |

**2차로 미룸** : Trails · SubEmitters · Collision · Triggers · Lights · External Forces · Force over Lifetime · Inherit/Limit Velocity · Custom Data · Mesh shape · Stretched Billboard. 레시피에 적으면 `recipe.unsupported` error 로 「못 옮긴 칸」을 알려 준다(조용히 버리지 않는다).

### 2-4. 다형 값 (숫자 칸)

| JSON 예 | 뜻 | Unity |
| --- | --- | --- |
| `0.3` | 상수 | `MinMaxCurve(0.3)` · Constant |
| `{"random": [0.2, 0.5]}` | 두 값 사이 | TwoConstants |
| `{"curve": [[0, 1], [0.5, 2], [1, 0]], "mult": 1, "step": true}` | 수명 곡선 `[t, v]`. `step` 이면 계단 | Curve (`AnimationCurve` · multiplier) |
| `{"random_curve": [[[0,1],[1,0]], [[0,2],[1,0]]]}` | 두 곡선 사이 | TwoCurves |
| `{"from": 2, "to": 0, "ease": "out"}` | 쉬운 꼴. ease = `linear` · `in` · `out` · `inout` | `check` 가 키 5개 `curve` 로 펼친다 |

- 곡선 키 2~8개, t 는 0~1 오름차순. 탄젠트는 안 받는다(자동 평활, `step` 이면 무한 = 계단). 벡터 칸(`position` · `rotation` · `box`)은 상수 `[x, y(, z)]` 만.
- `sizeOverLifetime` 곡선은 **기본 `step: true`** — 중간 크기는 텍셀에 반쯤 걸쳐 도트가 깨진다.
- resolved.json 에는 앞 네 꼴만 남는다. C# `VfxValue` 는 **Unity 4모드와 1:1** 인 넷만 안다. resolved 의 `curve` 에는 `mult` · `step` 이 늘 있다.
- resolved.json 최상위에는 `ppu` · `sortingLayer` · `snap` · `fixedDeltaTime`(0.02 고정)이 더 붙고, 층마다 `material` · `blend` · `texture`(절대 경로) · `sortOrder` · `space` · `offset` 이 늘 채워진다. `bursts` 는 늘 객체 꼴(`{t, n, cycles, interval}`)이다. C# 이 기본값을 짐작하지 않게 Python 이 다 채운다.

### 2-5. 색 값

| JSON 예 | 뜻 | Unity |
| --- | --- | --- |
| `"#FFE08A"` · `"#FFE08A80"` | hex(알파 붙여도 됨) | `MinMaxGradient(Color)` |
| `"p3"` | 프로필 팔레트 3번 | `check` 가 hex 로 바꿈 |
| `{"random": ["p0", "p2"]}` | 두 색 사이 | TwoColors |
| `{"gradient": {"color": [[0, "p0"], [1, "p3"]], "alpha": [[0, 1], [0.8, 0]]}, "mode": "fixed"}` | 수명 색 | Gradient. `mode` 기본 `fixed`(계단 색·알파) |
| `{"random_gradient": [g1, g2]}` | 두 그러데이션 사이 | TwoGradients |

색 키 · 알파 키는 각각 최대 8개(Unity 한도). `mode: blend` 는 프로필이 허락할 때만(8절). 그러데이션 색 키에는 8자리(알파 붙은) hex 를 안 받는다 — 알파는 `alpha` 키로만.

- **`fixed` 의 뜻은 「키 시각 t 부터 다음 키까지 그 값을 유지」**다. Unity Fixed 는 「t 에서 시각 ≥ t 인 첫 키 값」이라 그대로 넘기면 한 칸씩 앞당겨진다. C# 이 키 시각을 다음 키 시각으로 밀어 뜻을 맞춘다(구현 실측 4절).
- **Unity 는 `main.startColor` × `colorOverLifetime` 색을 곱한다.** 색은 startColor 에 두고 그러데이션 색 키는 `#FFFFFF` 로, 알파만 쓴다. 둘 다 색이면 `recipe.color_multiply` warn.

### 2-6. 예시 — 맞음 파편 (템플릿 없이 직접)

```json
{ "version": 1, "name": "hit_sparks_a", "profile": "../profile.json",
  "seed": 1234, "fixedTimeStep": true, "duration": 0.5, "canvas": { "texels": [64, 64], "scale": 4 },
  "layers": [{ "name": "sparks", "material": "unlit", "blend": "alpha", "sortOrder": 10,
    "main": { "startLifetime": { "random": [0.25, 0.45] }, "startSpeed": { "random": [40, 90] },
              "startSize": 1, "startColor": "p0", "gravityModifier": 0.6, "maxParticles": 64 },
    "emission": { "rateOverTime": 0, "bursts": [[0, 18]] },
    "shape": { "type": "Cone", "angle": 35, "radius": 1, "rotation": [-90, 0, 0] },
    "colorOverLifetime": { "color": { "gradient": {
      "color": [[0, "#FFFFFF"]], "alpha": [[0, 1], [0.8, 0]] } } },
    "sizeOverLifetime": { "size": { "curve": [[0, 2], [0.4, 1]] } } }] }
```

속도 40~90 은 텍셀/초, 크기 1 텍셀 × 곡선 2→1 (기본 계단). Cone 은 `[-90, 0, 0]` 으로 위로 쏜다. 색은 팔레트 0번(startColor), 그러데이션은 흰색에 알파만 — 0.8 까지 1, 그 뒤 0(`fixed`).
`profile` 이 `../` 로 레시피 폴더 밖을 가리키므로 `check` · `loop init` 에 `--input-root <위 폴더>` 를 준다.

## 3. VFX 프로필

### 3-1. 칸

| 칸 | 값 | 어디서 뽑나 | 기본값 | 레시피 제약 | 프레임 검수 |
| --- | --- | --- | --- | --- | --- |
| `palette` | hex 배열(최대 32) | 기준 PNG 고유 색(쓰인 칸 0.5% 이상) · 화풍 조각 | 없음(필수) | `p<n>` 풀이 · 팔레트 밖 hex 는 warn | 팔레트 거리 |
| `fx_extra` | hex 배열 | 손 | `["#FFFFFF"]` | 팔레트 밖이어도 허용할 색 | 같음 |
| `ppu` | 정수 | 화풍 조각 · 손(PNG 로는 못 뽑음) | 32 | 단위 바꾸기 | — |
| `pixel_size` | 정수 집합 | 기준 PNG 의 같은 색 줄 길이 최대공약수 | `[1, 2]` | `startSize` × 크기 곡선 키가 이 집합 안 | 입자 크기(덩어리 폭) |
| `max_colors` | 정수 | 화풍 조각 · 손 | 4 | 한 층 색 키 수 상한 | 배경 뺀 고유 색 수 |
| `outline` | `none` | 고정 | `none` | 외곽선 텍스처 안 받음(이펙트 규칙) | — |
| `fps` · `fps_range` | 정수 · `[min, max]` | 화풍 조각 frame_ms · 손 | 12 · `[12, 16]` | 플립북 `textureSheet.fps` 범위 | 판정 fps 기본 |
| `alpha_steps` | `binary` · `free` | 손 | `binary` | 색 `mode: blend` 금지 · 알파 키 0/1 | 반투명 칸 수 |
| `allow_rotation` | bool | 손 | true | false 면 `startRotation` · `rotationOverLifetime` 칸이 error | 회전 층은 격자 지표 안 봄 |
| `seq_tolerance` | `{ratio, run}` | 손 | `{ratio: 0.5, run: 3}` | — | 묶음 규칙 문턱(8-2) : 어긋난 프레임 비율 · 연속 장 수 |
| `max_particles` · `sorting_layer` | 정수 · 이름 | 손 | 256 · `Default` | 층 `maxParticles` 상한 · 렌더러 정렬 층 | — |
| `snap` · `bloom` | bool | 손 | true · false | 스냅 머티리얼 강제 · 레시피 `bloom` 기본 | 경계 텍셀 배수 비율 |

### 3-2. 입력과 덮기

- 명령 : `vfxtool profile --from ref1.png [--from ref2.png] [--style style.json] [--override hand.json] --out profile.json`.
- 기준 PNG : 게임 스프라이트 몇 장, **1:1 원본 크기**(확대본은 `pixel_size` 를 틀리게 뽑는다 → 가장 작은 줄 길이가 2 이상이면 warn). 알파 0 칸은 뺀다.
- 화풍 조각 JSON(ArtTool 산출물) : **아는 키만** 읽고 나머지는 무시. 키 ↔ 프로필 칸 대응표는 VFXTool `Docs/Guide/` 에 두고, 그쪽 형식이 바뀌면 이 표만 고친다.
- **이기는 순서** : 기본값 < PNG < 화풍 조각 < 손 덮기(`--override`). 칸마다 `"source"` 를 적는다. 손으로 고친 프로필도 `check` 가 같이 검사한다(팔레트 비었음 등은 종료 2).

## 4. 템플릿 층

### 4-1. 파일 꼴 (`src/vfxtool/templates/<name>.json`)

| 칸 | 뜻 |
| --- | --- |
| `version` · `name` · `title` | 판 · 이름 · 한국어 제목 |
| `layers[]` | 뼈대 층. 값 자리에 `"$count"` · `"$life*0.6"`(파라미터 · 파라미터 × 숫자) · `"@pixel_size"`(프로필 `pixel_size` 의 가장 작은 값) 참조를 쓴다 |
| `params` | 노출 파라미터 `{이름: {type, default, min, max, desc, fallback}}`. `fallback`(색만, 없어도 됨) : 기본값이 팔레트 밖 번호면 대신 쓸 다른 파라미터 이름. type = `int` · `float` · `color` · `bool` · `file` · `tiles`(`[x, y]` 정수) · `vec`(숫자 배열) |
| `fixed` | 템플릿이 못 박는 값(경로 → 값). AI 의 `override` 로도 못 바꾼다. 바꾸면 `recipe.fixed` error |
| `presets` | 이름 붙은 params 묶음(`small` · `big` 등) |
| `check[]` | 템플릿 전용 규칙 `{rule, layer, args}`. 8절 공통 규칙에 더해 돈다 |

레시피 층이 `"template": "hit_sparks"` 를 부르면 그 자리에 템플릿 층들이 `<층 이름>.<템플릿 층 이름>` 으로 펼쳐진다. 템플릿을 부르는 층에는 `template` · `params` · `preset` · `override` 말고 `offset` 만 더 적을 수 있다. 값 순서는 **뼈대 < preset < params < override(템플릿 층 이름별 모듈 덮기) — 단 fixed 는 늘 이긴다.** 펼친 결과는 resolved.json 에 남아 AI 가 다음 바퀴에 그대로 읽는다. 내장 템플릿은 `src/vfxtool/templates/`, 게임 쪽 템플릿은 `--templates <폴더>`(여러 번 가능)로 더한다. 같은 이름이면 뒤에 준 폴더가 이긴다.

### 4-2. 1차 템플릿 다섯

| 이름 | 층 | 쓰는 모듈 | 노출 파라미터 | 템플릿 check |
| --- | --- | --- | --- | --- |
| `hit_sparks` 맞음 파편 | 1 (`sparks`) | main · emission(burst) · shape Cone · colorOverLifetime · sizeOverLifetime | `count` · `spread` · `speed` · `life` · `color` · `gravity` | 버스트만(rate 0) · duration ≤ 0.6 · 끝 프레임 빔 |
| `land_dust` 착지 흙먼지 | 1 (`puff`) | main · emission(burst) · shape Edge(가로) · velocityOverLifetime(x 바깥, y 위 조금) · sizeOverLifetime(2→1 계단) · colorOverLifetime | `width` · `count` · `rise` · `life` · `color` | 무게중심 y 가 시작점 위 8텍셀 안 · 좌우 대칭(무게중심 x 차 ≤ 2텍셀) |
| `sparkle` 반짝임(플립북) | 1 (`twinkle`) | main · emission · shape Circle · textureSheet | `sheet`(file) · `tiles` · `size`(한 칸 텍셀) · `count` · `radius` · `life` | 시트 파일 있음 · 시트 크기가 tiles 로 나눠짐 · fps 가 `fps_range` 안 · 시작 프레임 랜덤 |
| `ambient_motes` 분위기 입자 | 1 (`motes`) | main · emission(rate) · shape Box · velocityOverLifetime · noise · colorOverLifetime | `area` · `density` · `drift` · `wobble` · `color` | `loop: true` · 첫 프레임부터 안 빔 · 덮은 면적 ≤ 5% |
| `heal_rise` 회복 입자 | 2 (`dots` · `glow`) | dots : main · emission · shape Circle · velocityOverLifetime(y 위) · colorOverLifetime / glow : 같은 꼴 additive | `radius` · `count` · `rise` · `color` · `glow`(bool, 끄면 층 뺌) · `glow_color`(기본 `p1`, fallback `color`) | 무게중심 y 가 오른다(마지막 > 처음) · glow 최대 밝기 ≤ 0.95 |

다섯 모두 `fixed` 로 `material` · `blend`(heal_rise glow 만 additive) · `space` · Frame Blending 끔을 못 박는다. `main.startSize` 기본은 `@pixel_size` 의 가장 작은 값(시트 텍스처 층인 sparkle 은 정수 텍셀 `size`).
내장 템플릿의 그러데이션 색 키는 `$color` 하나이거나 흰색이다 — 색 곱(2-5)으로 팔레트 밖 색이 안 나오게.

### 5-4. 진입점 인자 · job · result

| 인자 | 뜻 |
| --- | --- |
| `-batchmode -projectPath <P> -logFile <work>/unity.log` | Unity 표준. `-nographics` 는 `unity/run` 이 **넣지 못하게 막는다** |
| `-executeMethod Officina.Vfx.Editor.VfxEntry.Run` | 진입점 |
| `-vfxJob <work>/round_N/job.json` | 나머지는 다 job 파일로. 윈도 따옴표 · 길이 문제를 피하고 바퀴 기록으로 남는다 |

job.json 칸 : `recipe`(resolved.json 절대 경로) · `mode`(`build` 프리팹만 · `render` 렌더만 · `both`) · `saveRoot`(5-5) · `outDir`(PNG 자리, Unity 프로젝트 **밖**) · `frames`(`[{i, t}]`, 시각은 Python 이 셈 6-2) · `backgrounds`(기본 `["transparent"]`. `["black", "white"]` 는 옵션 — additive 층 디버그용으로 흑백 짝을 더 뽑는다).

```json
{ "status": "ok|issues|error", "unity": "6000.3.23f1", "recipeSha256": "…",
  "seed": 1234, "fixedTimeStep": true, "renderApi": "SingleCameraRequest",
  "prefab": "Assets/Vfx/Generated/hit_sparks_a/hit_sparks_a.prefab",
  "frames": [{ "i": 1, "t": 0.0833, "png": "f001.png", "particles": 18 }],
  "issues": [{ "rule": "build.unknown_field", "layer": "sparks", "detail": "main.foo" }],
  "seconds": { "build": 1.2, "render": 3.4 } }
```

종료 코드 : 0 = ok · 1 = issues(조립은 됐지만 못 옮긴 칸이 있음 등) · 2 = error(예외 · job 못 읽음 · 렌더 실패).

- **자리** : result.json 은 job.json 옆(`<work>/result.json`), 프레임은 `outDir` = `<work>/frames/`. render 는 resolved.json 사본도 `<work>/` 에 둔다(measure 가 `--recipe` 없이 읽게).
- result 에 칸 둘을 더했다 : `graphicsDevice`(렌더에 쓴 그래픽 장치 종류) · `fixedDeltaTime`.
- `t0_skipped` 는 따로 적는 칸이 아니라 frames 에 t ≤ 0 이 없음으로 센다.
- job.json 에 모르는 칸이 있으면 C# 이 거절한다(종료 2) — 오타가 조용히 무시되지 않게.

### 5-5. 저장 자리

- 기본 `Assets/Vfx/Generated/<name>/`(프리팹 · 층별 `.mat` · 복사한 텍스처 · `<name>.recipe.json` 옆 파일). `--save-root` 로 덮는다 — 게임 저장소는 자기 자리를 이 인자로 준다.
- `saveRoot` 는 정규화 뒤 `Assets/` 안이어야 한다(`..` · 절대 경로 · 조각 끝 공백 · 점 거절, C# 은 정션 · 심볼릭 · 끊긴 링크도 거절). 폴더에 `<name>.recipe.json` 옆 파일이 **없으면** 사람이 만든 것으로 보고 덮지 않는다(종료 2).
- 조각 앞 공백과 잘못된 파일 이름 글자(`Assets/a<b`)도 거절한다(C# 은 전체 Trim 없이 거절, 10-15 2차 리뷰).
- 프레임 PNG 는 Unity 프로젝트 밖(`--work`)에만 쓴다(`Assets/` 면 매번 가져오기가 돈다). 설정 · 배선은 코드에, 결과 값 · 모양은 프리팹에(스튜디오 공용 규칙 10절).

| `gif` | 바퀴 폴더 · `--scale k` | `preview.gif` — 프레임 순서, fps 는 레시피, 검정 배경 합성, nearest k 배, 끝에 0.5초 멈춤. 사람이 움직임을 보는 용도(AI 는 Read 가 GIF 프레임을 못 돌리니 sheet 로 본다) | × |
| `loop init` · `loop run` | 레시피 · `--work` · `--max N`(기본 4) | `loop.json` · `round_1/` · 그 바퀴 check → render → measure → sheet + gif 한 번에 | run 만 ○ |
| `loop next` · `loop best` | `--critic` · `--patch`(선택 — 없으면 판정만) | 순위 기록 · rollback · 다음 바퀴(patch 가 있으면 바로 돈다) 또는 멈춤 · 최고점 판. `best --build` 는 1차에 없다(최고점 판 resolved 로 `build` 를 따로 친다) | next 에 patch 면 ○ |
| `template list` · `show <name>` | `--templates <폴더>`(여러 번) | 내장 + 더한 폴더의 목록(어느 폴더 것인지 표시) · 템플릿 JSON + params 표 | × |
| `doctor` | `--project` | Unity 판 · Unity.exe · 잠금 · manifest 의 `com.officina.vfx` 줄 · Newtonsoft 줄 · Python 의존성 | × |

보고 꼴(모든 명령 공통, stdout JSON 한 덩어리) :

```json
{ "status": "ok|warn|fail|error",
  "issues": [{ "rule": "frame.palette", "layer": "sparks", "frame": 3, "severity": "warn",
               "detail": "팔레트 밖 색 #F0A040 12칸", "hint": ["main.startColor", "colorOverLifetime"] }],
  "metrics": { "colors": 3, "grid_ratio": 1.0, "coverage": [0.2, 1.1, 0.8] } }
```

종료 코드 : **0** = ok · warn · **1** = fail(error 규칙에 걸림 — 레시피 · 결과물 문제) · **2** = error(인자 · 파일 · Unity 못 찾음 · 잠금 · 타임아웃 · 예외). 인자 오류도 같은 JSON 을 stdout 에 쓰고 2 로 끝난다. 프레임 쪽 `layer` 는 층을 나눠 뽑지 않으므로 None 이 많다(층 탓으로 짚을 수 있는 규칙만 채움).

### 6-2. `unity/locate` · `unity/run` · 프레임 시각

- locate : `ProjectSettings/ProjectVersion.txt` → `C:\Program Files\Unity\Hub\Editor\<판>\Editor\Unity.exe`. `--unity` · 환경 변수 `VFXTOOL_UNITY` 로 덮기. 없으면 종료 2.
- 잠금 : 같은 프로젝트를 연 `Unity.exe`(명령줄 `-projectPath` 비교, 못 읽으면 「있다」)가 있으면 종료 2. 없고 `Temp\UnityLockfile` 을 배타로 열 수 있으면 남은 잠금으로 보고 진행.
- run : `Popen` 숨김 → `wait(timeout)`, 기본 300초(첫 판 컴파일 60초 실측). 넘으면 `taskkill /PID <pid> /T /F` 후 종료 2. 인자에 `-nographics` 가 있으면 거절. 실패하면 `unity.log` 의 `error CS` · `Exception` 줄을 issues 에 싣는다.
- **프레임 시각**(Python 이 셈, C# 은 따름) — one-shot : `t_i = i / fps`, `i = 1 … N`, `N = ceil((duration + 최대 startDelay + 최대 startLifetime) × fps)`, 상한 48. **t=0 은 안 뽑는다**(빈 그림, 보고 metrics 에 `t0_skipped: true`). loop : 한 바퀴 돈 뒤 `t_i = duration + i / fps`, `N = ceil(duration × fps)`. 상한 48 은 loop 에도 건다. 잘리면 `render.frames_capped` issue + metrics `truncated: true` 이고, 이때 `frame.last_not_empty` 는 warn 이 아니라 info 로 내린다(잘려서 끝이 안 보인 것이므로).
- **렌더 시간** : C# 은 프레임마다 절대 시각으로 `Simulate(t, withChildren: true, restart: true, fixedTimeStep)` 을 새로 돈다(앞 프레임에서 이어 돌리지 않음). 실측 ④ 의 결정성이 이 꼴에서 나왔다.

### 6-3. 접촉판 `sheet`

- 칸 : 한 프레임 = 캔버스 텍셀 × k(칸이 128px 이상 되는 가장 작은 정수), nearest 확대. 12칸마다 다음 묶음(두 줄 짝 유지).
- 줄 : 1줄 검정 배경 · 2줄 흰 배경 — Python 이 RGBA 프레임을 PIL 로 검정 · 흰 판 위에 합성해 만든다(Unity 는 한 번만 렌더). `--overlay` 면 3줄 — 팔레트 밖 칸 자홍 · 격자 어긋난 경계 노랑 · 무게중심 십자.
- 시간 띠 · 머리 : 칸 위에 `#3 t=0.250`, 맨 위에 `name · round N · seed · fts · error/warn 수`. PIL 기본 글꼴이라 ASCII 만.

**Python 파일 자리**(구현 뒤 실제) : `src/vfxtool/` 아래 `cli.py` · `errors.py` · `paths.py` · `report.py` · `commands/`(명령마다 한 파일 — `add_parser` · `run`) · `recipe/{values,colors,schema,fields,resolve,check,check_rules,profile_view,patch}.py` · `profile/{extract,merge,style,common,command}.py` · `template.py` · `template_values.py` · `template_rules.py` + `templates/*.json` · `unity/{locate,lock,run,job,guard,command}.py` · `frames.py`(RGBA 프레임 읽기 · 흑백 옵션이면 짝 읽기) · `measure.py` · `measure_metrics.py` · `measure_rules.py` · `measure_template.py` · `sheet.py` · `gif.py` · `loop.py` · `loop_state.py` · `loop_pipeline.py` · `symptoms.json`. `pyproject.toml` · `setup.ps1` 은 SoundTool 꼴(py 3.14 · `.venv` · editable + test extras · 연기 시험 `python -m vfxtool --help` · `.setup-stamp`). 의존성은 `pillow` · `numpy` 만.

## 7. 고리 관리

### 7-1. 바퀴 상한 = 4 (첫 판 + 고침 3) · 점수

- ParticleGen 은 4회 + rollback 으로 점수를 올렸다. rollback 으로 한 바퀴를 버려도 남는 바퀴가 있어야 한다.
- ArtTool 3바퀴는 칸을 손으로 찍는 고리라 한 바퀴가 비싸다. 여기는 patch 몇 줄 + Unity 약 20초라 싸다. 4바퀴로 안 되면 뼈대(템플릿 고르기)가 틀린 것이라 사람이 본다.
- **critic.json**(AI 가 씀) : `{"score": 0~1, "symptoms": ["too_dense", …], "notes": "…"}`. 증상은 7-2 표의 낱말만. 2바퀴부터는 앞 판 sheet 와 견줘 적는다.
- **판의 순위** : ① 프레임 error 수 적은 판 ② `score` 높은 판 ③ warn 수 적은 판, 다 같으면 나중 판. 기계 점수가 먼저다 — 보기에 좋아도 규칙을 어긴 판은 못 쓴다.
- 순위 · clean 판정에 세는 issue 는 **render · measure 것만**이다. check issue(레시피 warn 등)는 보고에만 싣는다 — 레시피 warn 이 판마다 같이 붙어 순위를 흐리지 않게.

### 7-2. 증상 ↔ 원인표 (Shuriken 용 초안)

| 증상 낱말 | 보이는 꼴(자동 탐지 규칙) | 먼저 볼 파라미터 |
| --- | --- | --- |
| `empty` | 모든 프레임 덮은 면적 0 (`frame.all_empty`) | `emission`(rate 0 + 버스트 없음) · `startDelay` > 길이 · `startColor` 알파 0 · 크기 0 |
| `offscreen` | 바깥 테두리 닿음 (`frame.clipped`) | `startSpeed` · `gravityModifier` · `startLifetime` · `shape.position` · `canvas` |
| `too_dense` | 덮은 면적 최대 > 문턱 | 버스트 수 · `rateOverTime` · `startSize` |
| `too_short` | 안 빈 프레임이 2장 이하 | `startLifetime` · `startSpeed`(너무 빨리 빠짐) |
| `lingers` | 끝 프레임이 안 빔 (`frame.last_not_empty`, one-shot) | `startLifetime` + `startDelay` > 길이 · `loop` |
| `off_palette` | 팔레트 밖 색 · 색 수 초과 | `colorOverLifetime.mode` · hex 대신 `p<n>` · additive 겹침 · 텍스처 |
| `off_grid` | 경계 배수 비율 < 1 인 프레임이 연속 3장 이상 · 또는 비율 문턱 넘음 (`frame.grid`, 묶음 규칙) | 스냅 아닌 머티리얼 · 크기 곡선 `step` 꺼짐 · 홀수 텍셀 시트 (회전 층은 안 봄) |
| `lopsided` | 무게중심 x 가 원점에서 치우침 | `shape.rotation` · `shape.angle` · `velocityOverLifetime.x` |
| `jittery` | 사람 눈(자동 없음) | `noise.strength` · `noise.frequency` · `scrollSpeed` |
| `too_bright` | 최대 밝기 ≥ 0.98 이 넓음(additive) | 입자 수 · 색 밝기(선형 기준으로 낮춤) · `blend` 를 alpha 로 |

`measure` 는 자동 탐지된 증상의 「먼저 볼 파라미터」를 `hint` 로 싣는다. 표는 `src/vfxtool/symptoms.json` 한 파일 — 고리를 돌며 늘린다.

### 7-3. patch 꼴 = 부분 덮기 (JSON Merge Patch 꼴 + 층 이름 열쇠)

```json
{ "layers": { "sparks": { "emission": { "bursts": [[0, 12]] }, "main": { "startSpeed": { "random": [30, 70] } } } },
  "duration": 0.45 }
```

- 규칙 : 객체는 겹쳐 합치고, 배열 · 값은 통째로 바꾸고, `null` 은 지운다(RFC 7396 과 같음). **`layers` 만 배열 대신 층 이름 열쇠**로 가리킨다. 없는 층 이름은 새 층(전체를 적어야 함).
- 거절 : `layers` 를 배열로 주면 `patch.layers_array` error. `profile` · `name` · `version` 을 바꾸면 `patch.fixed_field` error. 새 층은 `patch.new_layer` warn 이고, 이름에 점이 있거나 `main` 이 없으면 error(템플릿을 부르는 새 층은 `main` 없어도 됨).
- JSON Patch(RFC 6902)를 안 고른 까닭 : `/layers/0/main/startSpeed` 같은 번호 경로는 층 순서가 바뀌면 엉뚱한 곳을 고친다. AI 가 쓰기에도 길다. 부분 덮기는 레시피와 모양이 같아 그대로 읽힌다.
- patch 는 **템플릿 펼치기 전 레시피**(round_N/recipe.json)에 댄다. 템플릿 층을 고치려면 그 층의 `params` · `override` 를 고친다. `fixed` 를 건드리면 `check` 가 막는다.

### 7-4. rollback · 최고점 · 멈춤

- 새 판이 **최고점 판보다 순위가 낮으면** 그 patch 를 「효과 없음」으로 장부에 적고, 다음 바퀴는 **최고점 판 레시피**에서 시작한다(보고에 「버린 patch」로 알림).
- 빌드 실패(종료 2) · `check` fail 은 바퀴를 안 쓴다 — 같은 바퀴에서 patch 를 다시 받는다. 두 번 연달아 실패하면 한 바퀴로 센다. 그 실패 판은 rollback 값이 없고(None) 순위 맨 뒤 · 정체 셈에서 뺀다.
- critic 이 붙기 전 판은 rollback 판정을 미룬다. `loop next --patch` 는 선택이다 — 없으면 critic 을 붙여 판정만 한다. 바퀴 상한은 `loop init --max N`(기본 4).
- `run` · `next` 는 장부 폴더의 `loop.lock` 으로 한 판만 돈다(`loop.locked` error).
- 바퀴의 check 는 **원본 레시피 폴더 기준**으로 돈다. round 폴더로 옮긴 레시피의 상대 경로(`profile` · `texture`)를 고치지 않는다.
- 템플릿 프레임 규칙(`template.*`)은 펼치기 전 레시피(round 의 `recipe.json`, 단독 measure 는 `--source`)에서 읽고, 층을 나눠 뽑지 않으므로 판 전체 그림으로 잰다.
- **멈춤(하나라도)** : ① 프레임 error 0 · warn 0 · `score ≥ 0.9` ② 4바퀴 다 씀 ③ 두 바퀴 연속 rollback(정체). 까닭은 `loop.json` 에 적는다.
- 끝나면 `loop best` 가 **최고점 판**(마지막 판 아님)을 돌려주고 접촉판을 사용자에게 보인다. PixelLab 우회는 사용자가 그걸 보고 정한다.

**바퀴마다 남는 파일** : `<work>/<name>/loop.json`(장부 : 바퀴 · 순위 · rollback · 멈춤 까닭) 과 `round_N/` 아래 `recipe.json` · `resolved.json` · `patch.json`(2부터) · `job.json` · `result.json` · `unity.log` · `frames/f###.png`(흑백 옵션이면 `f###_k.png` · `f###_w.png` 더) · `measure.json` · `sheet.png` · `preview.gif` · `critic.json`.

## 8. 검수 규칙

### 8-1. 레시피 단계 (`check`, Unity 전)

| 규칙 | 보는 것 | 심각도 |
| --- | --- | --- |
| `recipe.schema` · `unsupported` · `fixed` | 모르는 칸(가까운 이름 제안) · 꼴 · 필수 칸 · 2차 모듈 칸 · 템플릿 fixed 바꿈 | error |
| `recipe.pixel_size` | `startSize` × 크기 곡선 키가 프로필 `pixel_size` 안 / 크기 곡선 `step` 꺼짐 | error / warn |
| `recipe.rotation` · `alpha_steps` · `gradient_keys` | `allow_rotation: false` 일 때만 회전 칸(기본 true 라 통과) · `binary` 인데 `mode: blend` 나 알파 키 0·1 밖 · 키 8개 넘음 | error |
| `recipe.palette` · `max_colors` · `additive` | 팔레트 · `fx_extra` 밖 hex · 한 층 색 키 > `max_colors` · additive 층(겹침으로 색 수 늚) | warn · warn · info |
| `recipe.flipbook` | 시트 없음 · tiles 로 안 나눠짐 · fps 가 `fps_range` 밖 | error |

| `recipe.max_particles` · `paths` | 상한 넘음 · `texture` · `profile` 이 레시피 폴더 · `--input-root` 밖이거나 심볼릭 링크 | error |
| `recipe.params` · `template.*` | 템플릿 params 꼴 · 범위 밖 · 템플릿 check(`burst_only` · `max_duration` · `loop` · `start_frame_random`) | error · warn |
| `recipe.color_multiply` · `bloom_later` | startColor 와 그러데이션 둘 다 색(곱해짐) · `bloom: true`(1차는 받기만) | warn |

구현 뒤 더한 것 :

- `recipe.palette` 는 `p<n>` 번호가 팔레트 밖이면 **error**(밖 hex 는 위 표대로 warn).
- 안 적은 `startSize` · `maxParticles` 는 Unity 기본값(startSize 1 유닛 = ppu 텍셀 · maxParticles 1000)으로 보고 `pixel_size` · `max_particles` 를 검사한다.
- 반투명 알파가 붙은 hex(`#RRGGBB80`)도 `binary` 프로필에서 `recipe.alpha_steps` 위반이다. 그러데이션 색 키에는 8자리 hex 를 안 받는다.
- 시트 텍스처 층은 `pixel_size` 대신 정수 텍셀 크기만 본다(한 칸 크기가 곧 입자 크기).
- 프로필 단계 `profile.upscaled`(확대본 의심)는 info.
- Unity 단계 규칙 : `build.unknown_field` · `bad_value` · `mixed_modes` · `material` · `material_missing` · `texture_missing` · `texture_bad` · `entry.exception` · `entry.bug` · `render.frames_capped` · `unity.no_result` · `unity.stale_lock`(info). 그 밖 `patch.*`(7-3) · `loop.locked` · `doctor.newtonsoft`.
- 증상 아닌 규칙의 힌트는 `symptoms.json` 의 `rule_hints` 표에 둔다.

### 8-2. 프레임 단계 (`measure`, 렌더 뒤)

**까닭** : 움직이는 이펙트는 사람 눈이 연속으로 보므로 중간 한 장이 깨져도 자연스럽다. 그래서 규칙은 프레임 한 장이 아니라 **묶음 단위**로 본다.

- **묶음 규칙** (`frame.grid` · `colors` · `palette` · `pixel_size`) : 프레임마다 어긋남을 재고, 어긋난 프레임 비율이 `seq_tolerance.ratio`(기본 0.5)를 넘거나 **연속 `run`(기본 3)장 이상** 어긋나면 warn. 한두 장 어긋남은 info.
- 회전 · 크기 곡선이 있는 층이 들어간 판은 `grid_ratio` 를 문턱에 안 대고 info 로 값만 보고한다(회전 중 경계는 격자에 안 맞는 게 정상).
- textureSheet 층이 있는 판은 `frame.pixel_size` 를 info 로만 낸다(시트 칸 안 그림 모양이 덩어리 폭을 정하므로).
- `frame.lopsided`(무게중심 x 평균 치우침) 문턱은 `max(2, 2 × 평균(spread_x / √blobs))` 텍셀이다. `spread_x` 는 덩어리 무게중심 x 표준편차, `blobs` 는 덩어리 수 — 입자가 적은 판의 우연 흔들림을 봐준다(10-15 2판).
- 문턱 상한은 캔버스 폭 1/4 : `min(문턱, max(2, width/4))`. 넓게 흩어진 판에서 문턱이 끝없이 커지지 않게 한다(10-15 2차 리뷰, metrics 에 `width`).

RGBA 프레임을 텍셀 해상도로 줄여(칸 가운데 픽셀) 재고, 알파는 PNG 알파를 그대로 쓴다. 흑백 옵션으로 뽑은 판만 `a = 1 − (흰 − 검정)` 복원식을 쓴다. additive 층은 알파가 One One 이라 1 로 나와 뜻이 없으니 밝기로만 본다.

| 지표 | 계산 | 문턱 출처 | 규칙 · 심각도 |
| --- | --- | --- | --- |
| 고유 색 수 `colors` | 배경과 다른 칸의 고유 RGB 수(프레임마다 · 전체) | `max_colors`(additive 층 있으면 ×2) · `seq_tolerance` | `frame.colors` 묶음 warn / info |
| 경계 배수 비율 `grid_ratio` | 원본 해상도에서 색 경계 좌표 중 `scale` 배수 비율 | `snap` 이면 프레임마다 1.0 · `seq_tolerance` | `frame.grid` 묶음 warn / info (회전 · 크기 곡선 층은 info 만) |
| 팔레트 거리 `palette_dist` | 칸마다 가장 가까운 팔레트 · fx_extra 색까지 RGB 거리의 최댓값 | 0(unlit) · lit 은 안 봄 · `seq_tolerance` | `frame.palette` 묶음 warn / info |
| 반투명 칸 `semi_alpha` · 알파 합 `alpha_sum` | 알파가 0 · 1 아닌 칸 수(알파 블렌드만 있는 판) · 프레임마다 알파 합(양의 흐름) | `binary` 면 0 · 보고만 | `frame.semi_alpha` warn · info |
| 덮은 면적 `coverage` | 배경과 다른 칸 % (프레임마다) | 템플릿 check · 기본 최대 40% | `frame.dense` warn |
| 무게중심 `centroid` | 덮은 칸의 평균 [x, y] (텍셀, 원점 = 이펙트 위치) | 템플릿 check | 템플릿 규칙 |
| 최대 밝기 `max_luma` | 선형 밝기 최댓값 · 0.98 넘는 칸 수 | 0.98 · 템플릿 | `frame.bright` warn |
| 빔 · 잘림 | 1번 면적 0 · 마지막 면적 > 0(one-shot) · 테두리 칸 덮음 · 모든 프레임 면적 0 | one-shot · loop 에 따라 | `frame.first_empty` · `last_not_empty` · `clipped` warn · `all_empty` error |
| 입자 크기 | 덮은 칸 덩어리 폭의 최빈값이 `pixel_size` 안 | 프로필 · `seq_tolerance` | `frame.pixel_size` 묶음 warn / info |

- 정정(10-15) : `palette_dist` 문턱은 0 이 아니라 4.0(`measure_metrics.PALETTE_TOLERANCE`)이다. Linear 색 공간의 꼭짓점 색 8비트 반올림을 흡수한다 — 근거는 `2026-10-15-변형묶음설계.md` 「구현 뒤 정정」 표.

**나누는 까닭** : 레시피 단계는 Unity 를 안 띄우고 1초 안에 끝나니 틀린 값은 여기서 다 걸러 Unity 판(20초)을 아낀다. 프레임 단계는 겹침 · 이동 · Noise 처럼 값만 봐선 모르는 결과를 본다. 같은 프로필 칸이 두 단계에 다 쓰인다(3-1 표의 두 열).
